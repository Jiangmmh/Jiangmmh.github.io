## 1. 使用Verilator进行仿真

### 1.1 何为仿真？

在Linux中进行RTL代码的开发并不困难, 创建一个RTL文件并在其中编写代码即可。但在完成RTL代码的开发工作后, 我们还需要一款仿真器来验证RTL代码所描述的电路是否符合预期。

> **仿真：在写好的硬件代码（RTL代码）被转换成具体的电路门之前，先用软件模拟的方式，检查它的逻辑功能是否符合你的设计意图。**
> 
- **RTL仿真（前仿真）**：发生在综合之前。基于RTL代码，在理想条件下验证功能是否正确。
- **综合**：把RTL代码翻译成由逻辑门组成的网表。
- **门级仿真**：综合之后，用带延迟信息的门电路网表再仿真一次，确认综合结果无误。

### 1.2 Verilator是什么？

![image.png](E4%20%E5%A4%84%E7%90%86%E5%99%A8%E7%9A%84%E4%BB%BF%E7%9C%9F%E5%92%8C%E9%AA%8C%E8%AF%81/image.png)

**Verilator是一个编译器**，它把可综合的 Verilog/SystemVerilog 代码“编译”成经过高度优化的 C++ 或 SystemC 模型，再借助本机 C++ 编译器生成最终的可执行文件来运行仿真。

**Verilator 的“Verilating”过程，本质是把硬件描述转换成软件程序：**

1. **读取与检查**：读取 Verilog/SystemVerilog 源码，进行语法和 Lint 检查。
2. **转换与优化**：将 HDL 转换成内部的抽象语法树（AST），然后执行一系列优化 pass，最终生成**多线程的 C++ 或 SystemC 源代码**（`.cpp` 和 `.h` 文件）。
3. **用户封装**：你需要自己写一个 C++ 的 `main()` 函数（wrapper），在里面实例化 Verilator 生成的模型对象，并编写激励逻辑。
4. **编译链接**：用 C++ 编译器（如 GCC/Clang）把 Verilator 生成的代码、你的 wrapper 以及 Verilator 运行时库一起编译，得到一个**原生可执行文件**。运行这个文件，就是在跑仿真。

**Verilator 的速度优势**（通常比解释型仿真器快 10-100 倍）源于几个核心设计：

- **周期精确，而非事件驱动**：它不模拟信号变化的每个细微事件，而是按**时钟周期**推进。这牺牲了门级延迟和毛刺的精度，但换来了巨大的速度提升。它主要处理“0”和“1”，对“X”和“Z”的处理有限且特殊。
- **激进优化**：在生成 C++ 之前，Verilator 会对设计做大量优化，比如常量传播、死代码消除、将组合逻辑转换为数据流图进行化简，甚至把 `case` 语句转换成更高效的 `if` 结构。
- **多线程与缓存友好**：它可以把设计**分区**成多个“宏任务”，静态分配到不同线程上并行执行。更关键的是，它会调整变量在内存中的布局，让同一个任务访问的变量在内存里挨在一起，以提高 CPU 缓存命中率。

查看Verilator手册，其主要使用方法是：

- 使用 `--binary` 选项时，Verilator 会将设计翻译成一个可执行文件，具体做法是生成 C++ 代码并对其进行编译。
- 使用 `--cc` 或 `--sc` 选项时，Verilator 会分别将设计翻译成 C++ 或 SystemC 代码。
- 使用 `--lint-only` 选项时，Verilator 会对设计进行 lint 检查以查看警告，但通常不会创建任何输出文件。
- 使用 `--json-only` 选项时，Verilator 会生成 JSON 输出，可用于提供给其他用户设计的工具。
- 使用 `-E` 选项时，Verilator 会按照 IEEE 预处理规则对代码进行预处理，并将输出写到标准输出。这对于提供给其他工具使用，以及调试“`define”语句是如何展开的，都很有用。

来看手册中给出的示例程序：

```bash
$ mkdir test_our
$ cd test_our

$ cat >our.v <<'EOF'
  module our;
     initial begin $display("Hello World"); $finish; end
  endmodule
EOF

$ cat >sim_main.cpp <<'EOF'
  #include "Vour.h"
  #include "verilated.h"
  int main(int argc, char** argv) {
      VerilatedContext* contextp = new VerilatedContext;
      contextp->commandArgs(argc, argv);
      Vour* top = new Vour{contextp};
      while (!contextp->gotFinish()) { top->eval(); }
      delete top;
      delete contextp;
      return 0;
  }
EOF
```

使用verilator编译：

```bash
$ verilator --cc --exe --build -j 0 -Wall sim_main.cpp our.v
```

解释该命令：

- `-cc` 用于获得 C++ 输出（而不是例如 SystemC，或仅做 lint 检查）。
- `-exe`，配合我们的 `sim_main.cpp` 封装文件，这样构建会创建一个可执行文件，而不只是一个库。
- `-build`，这样 Verilator 会自己调用 make。这样我们就不需要再单独手动调用一次 make。你也可以自己编写编译规则并自行运行 make，正如我们在“SystemC 执行示例”中展示的那样。
- `j 0`，让 Verilate 时使用机器拥有的尽可能多的 CPU 线程。
- `Wall`，让 Verilator 启用更强的 lint 警告。

最后，`our.v` 是我们的 SystemVerilog 设计文件。

双控开关模块的实现 top.v：

```verilog
module top(
  input a,
  input b,
  output f
);
  assign f = a ^ b;
endmodule
```

仿真程序如下：

- Verilator会对top.v进行编译，生成C++头文件和源文件，我们的top模块会作为类存储其中。
- 在仿真程序中只需要实例化它们即可使用。
- 在一次循环中, 代码将会随机生成两个1比特信号, 用来驱动两个输入端口, 然后通过`eval()`函数更新电路的状态, 这样我们就可以读取输出端口的值并打印。

```verilog
  #include <stdio.h>
  #include <stdlib.h>
  #include <assert.h>
  #include "Vtop.h"
  #include "verilated.h"

  int main(int argc, char** argv) {
      VerilatedContext* contextp = new VerilatedContext;
      contextp->commandArgs(argc, argv);
      Vtop* top = new Vtop{contextp};

      int n = 10;
      while (!contextp->gotFinish()) {
        int a = rand() & 1;
        int b = rand() & 1;
        top->a = a;
        top->b = b;
        top->eval();
        printf("a = %d, b = %d, f = %d\n", a, b, top->f);
        assert(top->f == (a ^ b));

        if (n-- <= 0) break;
      }

      delete top;
      delete contextp;
      return 0;
  }

```

查看[手册](https://veripool.org/guide/latest/faq.html)，修改仿真程序添加记录波形和导出，我用AI添加了注释。

```cpp
#include <stdio.h>      // printf
#include <stdlib.h>     // rand, srand
#include <assert.h>     // assert
#include <time.h>       // time，用于给 srand 提供种子
#include "Vtop.h"       // Verilator 根据顶层模块 top 自动生成的头文件，定义了 Vtop 类
#include "verilated.h"  // Verilator 运行时核心 API：VerilatedContext、Verilated 等
#include "verilated_vcd_c.h" // VCD 波形追踪支持：VerilatedVcdC

int main(int argc, char** argv) {
    // 1. 创建仿真上下文。它保存仿真时间、命令行参数、全局状态等。
    //    每个仿真进程通常只需要一个 VerilatedContext。
    VerilatedContext* contextp = new VerilatedContext;
    // 把 main 的命令行参数交给 Verilator，方便后续用 +verilator+... 之类的选项控制仿真
    contextp->commandArgs(argc, argv);

    // 2. 实例化被测设计（DUT）。Vtop 是 Verilator 为模块 top 生成的 C++ 类，
    //    构造函数接收 context 指针，把模型绑定到这个仿真上下文上。
    Vtop* top = new Vtop(contextp);
  
    // 3. 启用波形追踪。必须在 top->trace() 之前调用，否则 trace 不会生效。
    //    Verilator 5.x 推荐通过 context 设置；4.x 也可用 Verilated::traceEverOn(true)。
    contextp->traceEverOn(true);

    // 4. 创建 VCD 追踪器，并把它挂到 top 上。
    //    trace(tfp, 99) 的第二个参数是追踪深度（层级），99 表示追踪所有层级的信号。
    VerilatedVcdC* tfp = new VerilatedVcdC;
    top->trace(tfp, 99);

    // 5. 打开 VCD 输出文件。注意：目标目录必须已存在，否则 open 会静默失败。
    tfp->open("obj_dir/t_trace_ena_cc/simx.vcd");

    // 6. 用当前时间做随机种子，避免每次运行得到相同的激励序列。
    //    如果为了调试需要可复现，可以去掉这行或固定种子。
    srand(time(NULL));

    // 7. 主仿真循环：
    //    - contextp->gotFinish()：设计里若调用了 $finish，这里会变为 true，用于提前退出。
    //    - n-- > 0：后置减，先比较再减。n=10 时循环体执行 10 次，正好跑 10 个周期/激励。
    int n = 10;
    while (!contextp->gotFinish() && n-- > 0) {
        // 生成随机输入 a、b（各 1 bit）
        int a = rand() & 1;
        int b = rand() & 1;

        // 把激励写入 DUT 的输入端口。Verilator 生成的类把端口暴露为公有成员。
        top->a = a;
        top->b = b;

        // 8. eval() 是核心：它让模型根据当前输入计算所有组合逻辑和时序逻辑，
        //    更新输出端口和内部状态。每次改输入后都必须调用。
        top->eval();

        // 9. 推进仿真时间。Verilator 不会自动递增时间，
        //    若不调用 timeInc，所有 dump 的时间戳都是 0，波形会叠在一起。
        contextp->timeInc(1);

        // 10. 把当前时刻所有被追踪的信号值写入 VCD 文件。
        //     必须在 eval() 之后、时间推进之后调用，才能记录到最新状态。
        tfp->dump(contextp->time());

        // 打印本拍输入输出，便于肉眼核对
        printf("a = %d, b = %d, f = %d\n", a, b, top->f);

        // 11. 断言：检查 DUT 输出是否等于 a XOR b。
        //     若不等，assert 会中止程序，起到自检作用。
        assert(top->f == (a ^ b));
    }

    // 12. 收尾：关闭 VCD 文件（确保缓冲区刷盘），再释放追踪器和模型。
    //     顺序很重要：先 close，再 delete tfp，最后 delete top/contextp。
    tfp->close();
    delete tfp;
    delete top;
    delete contextp;

    return 0;
}
```

拷贝NVBoard的example目录下的main.cpp：

- 通过nvboard_bind_all_pins和脚本自动根据top.nxdc中的内容完成引脚绑定
- 使用nvboard_init初始化NVBoard
- 然后反复调用dut.eval在NVBoard上运行top模块

```cpp
#include <nvboard.h>
#include "Vtop.h"       

static TOP_NAME dut;

void nvboard_bind_all_pins(TOP_NAME* top);

static void single_cycle() {
  dut.clk = 0; dut.eval();
  dut.clk = 1; dut.eval();
}

static void reset(int n) {
  dut.rst = 1;
  while (n -- > 0) single_cycle();
  dut.rst = 0;
}

int main() {
  nvboard_bind_all_pins(&dut);
  nvboard_init();

  reset(10);

  while(1) {
    nvboard_update();
    single_cycle();
  }
}
```

思路和双控开关类似，先编写流水灯逻辑led.v：

- 使用一个寄存器位数组存储当前led状态
- 每个时钟周期都让led循环左移一位
- 其中用了count来减缓其流动速度，方便观察

```verilog
module led(
  input clk,
  input rst,
  output [15:0] ledr
);
  reg [31:0] count;
  reg [15:0] led;
  always @(posedge clk) begin
    if (rst) begin led <= 1; count <= 0; end
    else begin
      if (count == 0) led <= {led[14:0], led[15]};
      count <= (count >= 5000000 ? 32'b0 : count + 1);
    end
  end

  assign ledr = led;
endmodule
```

修改top.v：

```verilog
module top(
  input clk,
  input rst,
  output [15:0]ledr
);

  led my_led(
    .clk(clk), 
    .rst(rst), 
    .ledr(ledr));

endmodule
```

### 2.3 **静态代码检查**

Verilator还可以作为一个lint工具来对代码进行静态检查. 在命令行中给`verilator`传递`--lint-only`参数, Verilator将仅开展代码检查工作, 并以警告信息的方式指出可能存在问题的代码, 而不生成C++文件。特别地, 你还可以添加`-Wall`选项, 来让Verilator开启所有类型的检查, 让它帮助你找到更多的潜在问题。

在Makefile中加入lint命令：

```makefile
lint: $(VSRCS)
	$(VERILATOR) --lint-only -Wall \
		--top-module $(TOPNAME) \
		$(addprefix -I, $(INC_PATH)) \
		$(VSRCS)
```

在chisel/src/main/scala中分别实现Counter、Led流水灯逻辑和顶层模块，最后通过Main.scala输出SystemVerilog代码。

> 
> 
> 
> 当模块变多时，应该把每个硬件模块写成独立的 Chisel `Module`，再由顶层模块实例化它们；最终由 Chisel 一次性生成完整的 SystemVerilog。
> 
> 不需要每个模块单独生成一个 `.sv` 文件，也不需要手动把多个生成文件拼起来。一般来说，**Chisel 会将顶层及其子模块一起生成到一个 SystemVerilog 文件中，子模块可以作为独立的 RTL module 存在**。
> 

Counter模块：用于定时发出tick信号，驱动LED移动循环移动

```scala
import chisel3._

class Counter extends Module {
  val io = IO(new Bundle {
    val enable = Input(Bool())
    val value  = Output(UInt(32.W))
    val tick   = Output(Bool())
  })

  val count = RegInit(0.U(32.W))
  val tick = count === 4999999.U

  when(io.enable) {
    when(tick) {
      count := 0.U
    }.otherwise {
      count := count + 1.U
    }
  }

  io.value := count
  io.tick := tick
}
```

LED模块：流水灯逻辑

```scala
import chisel3._
import chisel3.util.Cat

class Led extends Module {
  val io = IO(new Bundle {
    val enable = Input(Bool())
    val ledr   = Output(UInt(16.W))
  })

  val led = RegInit(1.U(16.W))

  when(io.enable) {
    led := Cat(led(14, 0), led(15))
  }

  io.ledr := led
}
```

顶层模块：连接NVBoard与LED模块和Counter模块

```scala
import chisel3._

class top extends Module {
  val io = IO(new Bundle {
    val ledr = Output(UInt(16.W))
  })

  val my_counter = Module(new Counter)
  val my_led     = Module(new Led)

  // 计数器达到阈值时，触发 LED 移位
  my_led.io.enable := my_counter.io.tick
  my_counter.io.enable := true.B
  
  io.ledr := my_led.io.ledr
}
```

```makefile
TOPNAME = top  # 顶级模块名
NXDC_FILES = constr/top.nxdc  # 指定引脚绑定脚本
INC_PATH ?=

VERILATOR = verilator
VERILATOR_CFLAGS += -MMD --build -cc \

BUILD_DIR = ./build
OBJ_DIR = $(BUILD_DIR)/obj_dir
BIN = $(abspath $(BUILD_DIR)/$(TOPNAME))

# chisel相关变量
CHISEL_DIR = ./chisel
CHISEL_OUT = $(BUILD_DIR)/chisel
CHISEL_SV = $(abspath $(CHISEL_OUT)/top.sv)
CHISEL_SRCS = $(shell find $(CHISEL_DIR)/src/main/scala -name "*.scala")

# NVBoard
SRC_AUTO_BIND = $(abspath $(BUILD_DIR)/auto_bind.cpp)

# Create build directory
$(shell mkdir -p $(BUILD_DIR))

# Generate SystemVerilog with Chisel
chisel-generate: $(CHISEL_SV)

# 使用sbt运行Main函数
$(CHISEL_SV): $(CHISEL_SRCS) \
              $(CHISEL_DIR)/build.sbt \
              $(CHISEL_DIR)/project/build.properties
	mkdir -p $(CHISEL_OUT)
	cd $(CHISEL_DIR) && /usr/bin/sbt "runMain Main"
	test -f $(CHISEL_SV)

# Generate NVBoard pin binding
$(SRC_AUTO_BIND): $(NXDC_FILES)
	python3 $(NVBOARD_HOME)/scripts/auto_pin_bind.py $^ $@

# NVBoard build rules
include $(NVBOARD_HOME)/scripts/nvboard.mk
# 覆盖链接参数，确保静态库位于 SDL2 依赖库之前
LDFLAGS := $(NVBOARD_ARCHIVE) $(shell sdl2-config --libs) -lSDL2_image -lSDL2_ttf

# Chisel-generated SystemVerilog files
VSRCS = $(wildcard $(CHISEL_OUT)/*.sv)
VSRCS += $(wildcard $(CHISEL_OUT)/verification/*.sv)

# C/C++ sources
CSRCS = $(shell find $(CHISEL_DIR)/src/main/cpp -name "*.cpp")
CSRCS += $(SRC_AUTO_BIND)

# Verilator compile flags
INCFLAGS = $(addprefix -I, $(INC_PATH))
CXXFLAGS += $(INCFLAGS) -DTOP_NAME="\"V$(TOPNAME)\""

# Link NVBoard library
LDFLAGS += $(NVBOARD_ARCHIVE)

# Build executable
$(BIN): chisel-generate $(SRC_AUTO_BIND) $(CSRCS) $(NVBOARD_ARCHIVE)
	@rm -rf $(OBJ_DIR)
	$(VERILATOR) $(VERILATOR_CFLAGS) \
		--top-module $(TOPNAME) $(VSRCS) $(CSRCS) \
		$(addprefix -CFLAGS , $(CXXFLAGS)) \
		$(addprefix -LDFLAGS , $(LDFLAGS)) \
		--Mdir $(OBJ_DIR) --exe -o $(BIN)

# Default target
default: $(BIN)

all: default

# Build and launch NVBoard
run: $(BIN)
	$(BIN)

# Lint generated SystemVerilog
lint: chisel-generate
	$(VERILATOR) --lint-only -Wall \
		-Wno-UNUSEDSIGNAL \
		--top-module $(TOPNAME) \
		$(addprefix -I, $(INC_PATH)) \
		$(VSRCS)

clean:
	rm -rf $(BUILD_DIR)

.PHONY: default all clean run lint chisel-generate
```

```scala
import chisel3._
import chisel3.util._

class Mux(ways: Int, width: Int) extends Module {
  require(ways > 0, "ways must be positive")
  require(width > 0, "width must be positive")
  require((ways & (ways - 1)) == 0, "ways must be a power of 2")

  val selWidth = log2Ceil(ways)  // 选择信号位宽
  
  val io = IO(new Bundle {
    val sel = Input(UInt(selWidth.W))
    val in  = Input(Vec(ways, UInt(width.W)))
    val out = Output(UInt(width.W))
  })

  io.out := io.in(io.sel)
}
```

### 4.3 实验二：**译码器和编码器**

![image.png](E4%20%E5%A4%84%E7%90%86%E5%99%A8%E7%9A%84%E4%BB%BF%E7%9C%9F%E5%92%8C%E9%AA%8C%E8%AF%81/image%2023.png)

**实现8-3优先编码器：**

- 需要有一个使能端en控制是否对输入进行编码，如果en为false，默认输出0
- 使用when-elsewhen来实现优先编码

```scala
import chisel3._

class PriorityEncoder83 extends Module {
  val io = IO(new Bundle {
    val en    = Input(Bool())
    val in    = Input(UInt(8.W))
    val out   = Output(UInt(3.W))
    val valid = Output(Bool())
  })

  // 默认值：en=0 或输入全 0 时，输出 0，valid=0
  io.out   := 0.U
  io.valid := false.B
  
  when (io.en) {
    when (io.in(7)) {
      io.out   := 7.U
      io.valid := true.B
    }.elsewhen (io.in(6)) {
```

### **4.6 实验六：移位寄存器及桶形移位器**

**移位器的实现如下：**

```scala
import chisel3._
import chisel3.util._

class Shifter(n: Int) extends Module {
  val io = IO(new Bundle {
    val in    = Input(UInt(n.W))       // 待移位数据
    val shift = Input(UInt(log2Ceil(n + 1).W)) // 移位量 0~n
    val left  = Input(Bool())          // true=左移, false=右移
    val out   = Output(UInt(n.W))
  })
  
  io.out := Mux(io.left,
    io.in << io.shift,
    io.in >> io.shift
  )
}
```

**桶形移位器（barrel shifter）**是一种**单周期完成任意位数移位**的组合逻辑电路。它和"逐位移位"（每周期移一位）不同，通过**多级 Mux 级联**在 log⁡2nlog2*n* 级内完成 n*n* 位数据的任意移位，是 CPU 里 ALU 的常见部件。

> 在Chisel中直接按前面的代码实现即可，无需手动进行桶型移位。在执行逻辑综合后就能得到桶型移位器。
> 

**线性反馈移位寄存器（Linear Feedback Shift Register, LFSR）**是一种由**移位寄存器**和**反馈逻辑（异或）** 构成的电路，其反馈函数是寄存器某些位的线性组合（GF(2) 上的异或）。它广泛用于伪随机数生成、CRC 校验、数据加扰、BIST 测试等。

**实际工程中更推荐直接用 Fibonacci 版本：**

```verilog
import chisel3._
import chisel3.util._

class LFSR(n: Int, taps: Seq[Int]) extends Module {
  val io = IO(new Bundle {
    val en   = Input(Bool())   // 使能
    val out  = Output(UInt(n.W))
    val bit  = Output(Bool())  // 当前移出的位（可作为伪随机比特流）
  })
	
  require(taps.nonEmpty, "至少需要一个抽头")
  require(taps.forall(t => t >= 0 && t < n), "抽头位置必须在 0~n-1")

  val reg = RegInit(1.U(n.W))  // 初值不能全 0

  // 反馈 = 所有抽头位的异或
  val feedback = taps.map(i => reg(i)).reduce(_ ^ _)

  when(io.en) {
    reg := (reg >> 1) | (feedback << (n - 1))  // 右移，反馈到最高位
  }

  io.out := reg
  io.bit := reg(0)  // 右移时最低位是移出的位
}
```

### 4.7 **实验七：状态机及键盘输入**

有限状态机（Finite State Machine, FSM）是**用有限个状态来描述时序行为**的模型。它在每个时钟沿根据**当前状态**和**输入**决定**下一状态**，并产生**输出**。一个 FSM 由五要素构成：

1. **状态集合** S：有限个状态，如 `IDLE`、`RUN`、`DONE`。
2. **输入集合** I：外部输入信号。
3. **输出集合** O：外部输出信号。
4. **状态转移函数** δ:S×I→S：当前状态 + 输入 → 下一状态。
5. **输出函数** λ：决定输出，**这是 Moore 和 Mealy 的分水岭**。

> 硬件实现上，FSM 通常拆成两部分：**状态寄存器**（时序逻辑，存当前状态）和**次态/输出组合逻辑**。
> 

有限状态机由组合逻辑电路和时序逻辑电路的组合而成。其中时序逻辑负责存储状态（寄存器），组合逻辑分为两个部分：

- 一个用于**产生**有限状态机的**下一个状态**的**次态逻辑**
- 另一个是用于**产生输出信号**的**输出逻辑**

有限状态机被分为两种：Moore（摩尔）型有限状态机和Mealy（米里）型有限状态机

- **Moore 型**
    - **输出只取决于当前状态**，与输入无关
    - 优点：输出在时钟沿后稳定，**无组合逻辑毛刺**，时序好分析。
    - 缺点：对输入的响应要**晚一个周期**（输入先改变状态，下一周期输出才变），达到同样功能可能需要更多状态。
    - 典型例子：交通灯——灯的颜色只由当前状态决定。
- **Mealy型**
    - **输出取决于当前状态和当前输入**
    - 优点：对输入**立即响应**（同一周期输出就变），状态数通常更少。
    - 缺点：输出是组合逻辑，**输入变化可能引起输出毛刺**；输出与输入时序耦合，分析更麻烦。
    - 典型例子：序列检测器——检测到输入序列时立即拉高输出。

[https://app.notion.com](https://app.notion.com)

> 
> 
> 
> **Verilog**的FSM推荐使用**三段式：一段状态寄存器、一段次态组合逻辑、一段输出逻辑**。这样 Moore/Mealy 的差别只体现在输出段。
> 

**Moore型的Verilog的写法：**

```verilog
module moore_fsm (
    input  wire clk,
    input  wire rst_n,
    input  wire in,
    output reg  out
);
    // 状态编码
    localparam S0 = 2'd0, S1 = 2'd1, S2 = 2'd2;
    reg [1:0] state, next_state;
		
    // 第一段：状态寄存器
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= S0;
        else        state <= next_state;
    end

    // 第二段：次态组合逻辑
    always @(*) begin
        next_state = state;          // 默认保持，防止 latch
        case (state)
            S0: next_state = in ? S1 : S0;
            S1: next_state = in ? S2 : S0;
            S2: next_state = in ? S2 : S0;
            default: next_state = S0;
        endcase
    end

    // 第三段：输出只由状态决定（Moore型）
    always @(*) begin
        case (state)
            S0: out = 1'b0;
            S1: out = 1'b0;
            S2: out = 1'b1;
            default: out = 1'b0;
        endcase
    end
endmodule
```

**Mealy型的Verilog的写法：三段式**

```verilog
module mealy_fsm (
    input  wire clk,
    input  wire rst_n,
    input  wire in,
    output reg  out
);
    localparam S0 = 1'b0, S1 = 1'b1;
    reg state, next_state;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= S0;
        else        state <= next_state;
    end

    always @(*) begin
        next_state = state;
        case (state)
            S0: next_state = in ? S1 : S0;
            S1: next_state = in ? S1 : S0;
            default: next_state = S0;
        endcase
    end

    // 输出依赖 state 和 in（Mealy）
    always @(*) begin
        case (state)
            S0: out = 1'b0;
            S1: out = in;      // 输入直接影响输出
            default: out = 1'b0;
        endcase
    end
endmodule
```

> **Chisel** 里 FSM 的惯用写法是 `ChiselEnum` + `RegInit` + `switch`/`when`，或者用 `chisel3.util` 的 `Enum` 和 `MuxCase`。推荐用 `ChiselEnum`，类型安全、可读性好。
> 

**Moore型的Chisel的写法**

```scala
import chisel3._
import chisel3.util._

class MooreFSM extends Module {
  val io = IO(new Bundle {
    val in  = Input(Bool())
    val out = Output(Bool())
  })
	
	// 定义状态
  object State extends ChiselEnum {
    val s0, s1, s2 = Value
  }
  
  val state = RegInit(State.s0)
	
	// 次态逻辑
  switch(state) {
    is(State.s0) { state := Mux(io.in, State.s1, State.s0) }
    is(State.s1) { state := Mux(io.in, State.s2, State.s0) }
    is(State.s2) { state := Mux(io.in, State.s2, State.s0) }
  }

  // 输出逻辑，输出只取决于 state（Moore）
  io.out := (state === State.s2)
}
```

**Mealy型的Chisel的写法**

```scala
import chisel3._
import chisel3.util._

class MealyFSM extends Module {
  val io = IO(new Bundle {
    val in  = Input(Bool())
    val out = Output(Bool())
  })

  object State extends ChiselEnum {
    val s0, s1 = Value
  }

  val state = RegInit(State.s0)
	
  switch(state) {
    is(State.s0) { state := Mux(io.in, State.s1, State.s0) }
    is(State.s1) { state := Mux(io.in, State.s1, State.s0) }
  }
	
  // 输出依赖 state 和 in（Mealy）
  io.out := (state === State.s1) && io.in
}
```

> **问题：为什么 Chisel 实现中无需 nextState？**
> 

因为 Chisel 的 `Reg` 赋值语义本身就是“次态逻辑”，不需要你手动把“当前状态”和“次态”拆成两个变量。**`state := ...` 这个赋值，语义上就是“下一个时钟沿 state 取这个值”**，也就是它**天然就是次态逻辑**。

Chisel 编译器（Firrtl）会自动把“读”和“写”分开：读走寄存器的 Q 端，写走 D 端前的组合逻辑。所以你不需要显式声明 `next_state`，**`Reg` 的“当前值”和“下一值”在语言层面被统一成了一个变量**，由赋值时机（时钟沿）来区分。

- **读 `state`**：拿到的是当前周期的状态（寄存器输出）。
- **写 `state := expr`**：`expr` 是组合逻辑算出来的次态，在下一个时钟沿生效。

> **问题：`ChiselEnum` 中的 `Value` 是什么？**
> 

这里 `ChiselEnum` 是一个类，`object State extends ChiselEnum` 创建了一个**枚举类型的单例对象**。`Value` 是这个类里定义的一个**方法/工厂，**每调用一次 `Value`，就**注册一个新的枚举常量**并返回它。

`Value` 是 `ChiselEnum` 内部定义的一个**类型成员**，代表“这个枚举的一个取值”。

其作用可以概括为：

1. **声明枚举常量**：每写一次 `Value` 就多一个合法状态。
2. **赋予类型**：返回值的类型是 `State.Type`，让 `switch`/`is` 能做类型检查、让 `RegInit(State.s0)` 推断出正确的寄存器类型和位宽。
3. **自动编码**：`ChiselEnum` 会给每个 `Value` 分配一个 `UInt` 编码（默认按声明顺序，也可用 `Value(3.U)` 之类指定），最终综合成硬件里的状态编码。

这行 Scala 代码**不是**“调用三次 `Value`”，而是**一次调用、三次引用**。这是个很容易踩的语法陷阱。

```scala
val Red, Green, Blue = Value
```

实际上等价于：

```scala
val Red = Value
val Green = Value
val Blue = Value
```

```scala
class ALU extends Module {
  val io = IO(new Bundle {
    val op    = Input(UInt(1.W))  // 0 = ADD，1 = SHL
    val a     = Input(UInt(32.W))
    val b     = Input(UInt(32.W))
    val shamt = Input(UInt(5.W))
    val result = Output(UInt(32.W))
  })
  
  io.result := Mux(io.op === 0.U, io.a + io.b, io.a << io.shamt)
}
```

构建立即数生成器：根据不同指令，输出不同的立即数。

```scala
import chisel3._
import chisel3.util._

/**
 * 立即数生成器
 *
 * 两种立即数格式：
 *   LI  : imm = instr[1:0]            零扩展
 *   BNE : offset = instr[5:2]         4 bit 有符号数，符号扩展
 * 由 isBranch 选择输出哪一个。
 */
class ImmGen extends Module {
  val io = IO(new Bundle {
    val instr    = Input(UInt(8.W))
    val isBranch = Input(Bool()) // 1 = 取分支偏移，0 = 取 LI 立即数
    val imm      = Output(UInt(32.W))
  })
  
  val liImm  = io.instr(1, 0).pad(32)                      // LI：2 bit 零扩展
  val offset = Cat(Fill(28, io.instr(5)), io.instr(5, 2))   // BNE：4 bit 符号扩展
	
  io.imm := Mux(io.isBranch, offset, liImm)
}
```

简单的程序计数器PC：

```scala
import chisel3._

/**
 * 程序计数器 PC
 *
 * 指令宽度 8 bit，PC 按「指令条数」计数：每执行一条指令 +1；
 * 分支跳转时 PC = PC + sign_ext(offset)（基准为分支指令自身的 PC）。
 * PC 用 32 bit 实现，取低 8 bit 去索引指令 ROM，越界后自然回绕。
 */
class PC extends Module {
  val io = IO(new Bundle {
    val next = Input(UInt(32.W))  // 下一条指令的地址
    val pc   = Output(UInt(32.W)) // 当前指令的地址
  })

  val pcReg = RegInit(0.U(32.W))

  pcReg := io.next
  io.pc := pcReg
}
```

实现Regfile，支持同时读取两个寄存器和写一个寄存器，使用信号we控制写使能

```scala
import chisel3._

/**
 * 寄存器堆：4 个 32 bit 通用寄存器，2 个组合读口 + 1 个同步写口
 *
 * 注意：r0 是可写的（程序要用 r0 保存比较用的常数），所以不做「恒 0」处理。
 * regs 是 4 个寄存器的调试输出：
 *   - 分支指令需要比较 R[0] 与 R[rs2]
 *   - io 指令写设备时需要取 R[rd]（rd 与 rs1/rs2 是不同的字段）
 */
class RegFile extends Module {
  val io = IO(new Bundle {
    val rs1  = Input(UInt(2.W))
    val rs2  = Input(UInt(2.W))
    val rd   = Input(UInt(2.W))
    val data = Input(UInt(32.W))
    val we   = Input(Bool())

    val out1 = Output(UInt(32.W))       // R[rs1]
    val out2 = Output(UInt(32.W))       // R[rs2]
    val regs = Output(Vec(4, UInt(32.W))) // 调试口：R[0..3]
  })

  // 初始化4个32位寄存器
  val regs = RegInit(VecInit(Seq.fill(4)(0.U(32.W))))

  when (io.we) {
    regs(io.rd) := io.data
  }

  io.out1 := regs(io.rs1)
  io.out2 := regs(io.rs2)
  io.regs := regs
}
```

实现一个简单的RAM，从prog.hex中读取指令：

```scala
import chisel3._

/**
 * 指令 ROM
 *
 * 程序放在 src/main/resources/prog.hex 里，展开期读进来（每行一个 8 bit 指令，
 * 支持 "//" 或 "#" 注释以及 "@地址" 定位）。
 *
 * 没有被程序用到的地址填 0xC0：
 *   0xC0 = op 11 | offset 0000 | rs2 00 → 条件 R[0] != R[0] 恒假，是条不改任何状态的 NOP。
 *   （不能填 0x00：0x00 会被译成 add r0,r0,r0，把用作比较基准的 r0 翻倍。）
 *
 * 如果想换成 $readmemh 语义，可以把下面的解析换成
 *   loadMemoryFromFileInline(mem, "prog.hex")
 * 代价是未定义地址会变成 0x00（上面说的坑），且文件路径要和仿真时的 CWD 对得上。
 */
class Memory extends Module {
  val io = IO(new Bundle {
    val addr = Input(UInt(8.W))
    val data = Output(UInt(8.W))
  })
	
  private val depth = 256
  private val nop   = 0xc0

  /** 解析 prog.hex，返回地址 -> 指令字节 的序列 */
  private def parseProgram: Seq[(Int, Int)] = {
    val stream = getClass.getResourceAsStream("/prog.hex")
    require(stream != null, "找不到 prog.hex（应放在 src/main/resources/ 下）")
    val lines = scala.io.Source.fromInputStream(stream).getLines().toSeq
    
    var addr = 0
    val out = scala.collection.mutable.ArrayBuffer[(Int, Int)]()
    lines.foreach { raw =>
      val line = raw.split("//").head.split("#").head.trim
      if (line.nonEmpty) {
        if (line.startsWith("@")) {
          addr = Integer.parseInt(line.drop(1).trim, 16)
        } else {
          out += ((addr, Integer.parseInt(line, 16) & 0xff))
          addr += 1
        }
      }
    }
    out.toSeq
  }

  val contents = Array.fill(depth)(nop)
  parseProgram.foreach { case (addr, value) =>
    require(addr < depth, s"prog.hex 里出现了越界地址 0x$addr%02x")
    contents(addr) = value
  }
  
  val rom = VecInit(contents.map(_.U(8.W)))
  io.data := rom(io.addr)
}
```

实现控制器：输入指令，输出对应控制信号

```scala
import chisel3._
import chisel3.util._

/**
 * 指令译码器（唯一的控制单元）
 *
 * 8 bit 指令格式：
 *   op = instr[7:6]
 *   00 | rd[5:4] | rs1[3:2] | rs2[1:0]   ADD : R[rd] = R[rs1] + R[rs2]
 *   01 | rd[5:4] |  dir[3]  | idx[2:0]   IO  : dir=0 读设备 / dir=1 写设备
 *   10 | rd[5:4] |   s[3:2] | imm[1:0]   LI  : R[rd] = imm << (s << 1)
 *   11 | offset[5:2] | rs2[1:0]          BNE : if (R[0] != R[rs2]) PC = PC + sign_ext(offset)
 */
class Controler extends Module {
  val io = IO(new Bundle {
    val instr = Input(UInt(8.W))

    // ---- 译码出的字段 ----
    val op     = Output(UInt(2.W)) // 00 ADD, 01 IO, 10 LI, 11 BNE
    val rd     = Output(UInt(2.W)) // 目的寄存器
    val rs1    = Output(UInt(2.W)) // ADD 的源寄存器 1
    val rs2    = Output(UInt(2.W)) // ADD / BNE 的源寄存器 2
    val imm    = Output(UInt(2.W)) // LI 的立即数
    val shamt  = Output(UInt(3.W)) // LI 的移位量 s << 1
    val ioDir  = Output(Bool())    // IO 方向：1 = 写设备，0 = 读设备
    val devIdx = Output(UInt(3.W)) // IO 的设备编号
    val offset = Output(UInt(4.W)) // BNE 的偏移（未符号扩展）
		
    // ---- 控制信号 ----
    val regWrite = Output(Bool())  // 写寄存器堆
    val devWrite = Output(Bool())  // 写设备
    val devRead  = Output(Bool())  // 读设备
    val branch   = Output(Bool())  // 是分支指令
    val aluOp    = Output(UInt(1.W)) // 0 = ADD，1 = SHL（LI 用）
  })

  val instr = io.instr
  val op    = instr(7, 6)

  io.op     := op
  io.rd     := instr(5, 4)
  io.rs1    := instr(3, 2)
  io.rs2    := instr(1, 0)
  io.imm    := instr(1, 0)
  io.shamt  := Cat(instr(3, 2), 0.U(1.W)) // s << 1
  io.ioDir  := instr(3)
  io.devIdx := instr(2, 0)
  io.offset := instr(5, 2)
  
  io.aluOp    := op === 2.U                  // 只有 LI 走移位
  io.branch   := op === 3.U
  io.devWrite := (op === 1.U) && io.ioDir
  io.devRead  := (op === 1.U) && !io.ioDir
  io.regWrite := (op === 0.U) || (op === 2.U) || io.devRead
}
```

实现设备逻辑：

```scala
import chisel3._
import chisel3.util._

/**
 * 外设设备表
 *
 * io 指令的语义：
 *   dir = 0（输入）：从编号为 idx 的设备读出 8 bit 数据，写入 R[rd]
 *   dir = 1（输出）：把 R[rd] 的低 8 bit 数据送到编号为 idx 的设备
 *
 * 设备编号：
 *   0 : 输出设备（七段数码管），读回上次写入的值
 *   1 : 输入设备（拨杆开关），读回开关的值；写入被忽略
 *   其他：读回 0，写入忽略
 */
class Device extends Module {
  val io = IO(new Bundle {
    val idx     = Input(UInt(3.W))  // 设备编号
    val isWrite = Input(Bool())     // 1 = 写设备，0 = 读设备
    val wdata   = Input(UInt(8.W))  // 写设备的数据（R[rd] 的低 8 位）
    val rdata   = Output(UInt(8.W)) // 读设备的数据
    val sw      = Input(UInt(8.W))  // 输入设备（拨杆开关）的值
    val out     = Output(UInt(8.W)) // 输出设备当前的值（送七段译码器）
  })
  
  val outReg = RegInit(0.U(8.W))
  when (io.isWrite && io.idx === 0.U) {
    outReg := io.wdata
  }
  
  io.out := outReg
  io.rdata := MuxLookup(io.idx, 0.U(8.W))(Seq(
    0.U -> outReg, // 输出设备：读回上次写入的值
    1.U -> io.sw   // 输入设备：读回拨杆开关
  ))
}

```

最后在Top模块中连接各组件：

- **`(7, 0)`** 是 Chisel 的**位选择（bit extraction）**语法，表示取第 7 位到第 0 位（共 8 位）

```scala
import chisel3._
import chisel3.util._

/**
 * sCPU 顶层：单周期 CPU
 *
 * 取指 → 译码 → 读寄存器 → 运算 / 访设备 → 写回 → 更新 PC
 *
 * 顶层端口（见 constr/top.nxdc）：
 *   sw     输入设备（拨杆开关）
 *   led    输出设备当前的值
 *   seg0   七段数码管 0：SEG0A..SEG0G + DEC0P
 *   seg1   七段数码管 1：SEG1A..SEG1G + DEC1P
 *   pcOut  当前 PC（低 8 bit，调试用）
 *
 * 位序约定：nvboard_bind_pin 把 nxdc 里写的第一个引脚接到信号的最高位，
 *   所以 nxdc 写 (SEG0A, SEG0B, …, DEC0P) 对应 seg0[7]=A … seg0[1]=G, seg0[0]=小数点。
 */
class top extends Module {
  val sw    = IO(Input(UInt(8.W)))
  val led   = IO(Output(UInt(8.W)))
  val seg0  = IO(Output(UInt(8.W)))
  val seg1  = IO(Output(UInt(8.W)))
  val pcOut = IO(Output(UInt(8.W)))

  // ---------------- 取指 ----------------
  val pc  = Module(new PC)
  val mem = Module(new Memory)
  mem.io.addr := pc.io.pc(7, 0)
  val instr = mem.io.data

  // ---------------- 译码 ----------------
  val ctrl = Module(new Controler)
  ctrl.io.instr := instr

  // ---------------- 立即数 ----------------
  val immGen = Module(new ImmGen)
  immGen.io.instr := instr
  immGen.io.isBranch := ctrl.io.branch

  // ---------------- 寄存器堆 ----------------
  val rf = Module(new RegFile)
  rf.io.rs1 := ctrl.io.rs1
  rf.io.rs2 := ctrl.io.rs2
  rf.io.rd := ctrl.io.rd
  rf.io.we := ctrl.io.regWrite

  // ---------------- ALU ----------------
  val alu = Module(new ALU)
  alu.io.op := ctrl.io.aluOp
  alu.io.a := Mux(ctrl.io.aluOp === 1.U, immGen.io.imm, rf.io.out1) // LI 用立即数，ADD 用 R[rs1]
  alu.io.b := rf.io.out2
  alu.io.shamt := ctrl.io.shamt

  // ---------------- 设备 ----------------
  val dev = Module(new Device)
  dev.io.idx := ctrl.io.devIdx
  dev.io.isWrite := ctrl.io.devWrite
  dev.io.wdata := rf.io.regs(ctrl.io.rd)(7, 0) // 写设备时送 R[rd] 的低 8 位
  dev.io.sw := sw
  
  // ---------------- 写回 ----------------
  val wbData = MuxLookup(ctrl.io.op, 0.U(32.W))(Seq(
    0.U -> alu.io.result, // ADD
    1.U -> dev.io.rdata,  // IO 读
    2.U -> alu.io.result  // LI
  ))
  rf.io.data := wbData

  // ---------------- 更新 PC ----------------
  // 分支条件：R[0] != R[rs2]；目标地址 = 当前 PC + sign_ext(offset)
  val branchTaken = ctrl.io.branch && (rf.io.regs(0) =/= rf.io.out2)
  pc.io.next := Mux(branchTaken, pc.io.pc + immGen.io.imm, pc.io.pc + 1.U)

  // ---------------- 输出 ----------------
  // 输出设备的值（8 bit 二进制）拆成十位、个位，各送一个七段译码器
  val tens = (dev.io.out / 10.U)(3, 0)
  val ones = (dev.io.out % 10.U)(3, 0)

  val dec0 = Module(new SegDecoder) // 个位 → seg0
  val dec1 = Module(new SegDecoder) // 十位 → seg1
  dec0.io.num := ones
  dec1.io.num := tens

  // SegDecoder 的输出是 {g,f,e,d,c,b,a}（bit0=a，共阳极 0 点亮）；
  // 这里重排成 {A,B,C,D,E,F,G,小数点}：A 在最高位，小数点接 1（常灭）
  def toSeg(dec: SegDecoder): UInt =
    Cat(dec.io.seg(0), dec.io.seg(1), dec.io.seg(2), dec.io.seg(3), dec.io.seg(4), dec.io.seg(5), dec.io.seg(6), 1.U(1.W))

  led := dev.io.out
  seg0 := toSeg(dec0)
  seg1 := toSeg(dec1)
  pcOut := pc.io.pc(7, 0)
}

```

## 6. 实现模拟器sEMU

![image.png](E4%20%E5%A4%84%E7%90%86%E5%99%A8%E7%9A%84%E4%BB%BF%E7%9C%9F%E5%92%8C%E9%AA%8C%E8%AF%81/image%2032.png)

> 关键问题：设计处理器芯片为什么还需要实现一个EMU？
> 

现在sISA只有4条指令, sCPU上运行的数列求和程序也很简单, 即使RTL实现有误, 靠波形进行调试也并不困难. 但随着处理器和程序变得复杂, 从大量的波形信息中找到错误, 将会变得很困难。

有没有一种高效的调试方法能够有效地验证处理器实现的正确性？有的！Difftest就是一个很棒的验证方法。进行DiffTest需要提供一个和**DUT(Design Under Test, 测试对象)** 功能相同但实现方式不同的**REF(Reference, 参考实现)**, 然后让它们接受相同的有定义的输入, 观测它们的行为是否相同。当两者的行为有差异时, 通常预示着DUT在相应输入下存在bug。

先来定义好sEMU的接口，这些函数会被npc中的主程序所调用：

```c
#pragma once
#include <cstdint>
#include <string>

// ---------------------------------------------------------------------------
// sEMU —— sCPU（chisel 实现）的软件参考模型，作为 chisel 处理器的 difftest REF。
//
// 行为严格对齐 npc/chisel/src/main/scala/ 下各模块，与 RTL 逐周期一致：
//   PC.scala        32bit PC，复位值 0，取低 8 bit 索引 ROM，越界自然回绕
//   Memory.scala    256 字节 ROM，未定义地址填 0xC0（NOP）
//   Controler.scala 指令译码
//   ImmGen.scala    LI 立即数零扩展；BNE 偏移 4bit 符号扩展
//   ALU.scala       ADD / SHL，32bit 运算
//   RegFile.scala   4 x 32bit，r0 可写
//   Device.scala    设备0 = 输出寄存器（送七段数码管）；设备1 = 输入（拨杆开关）
//   Top.scala       取指 → 译码 → 读寄存器 → 运算/访设备 → 写回 → 更新 PC
//
// GPR 用连续的字节数组保存（little-endian），这样 difftest 可以直接
//   uint8_t* dut_regs = ...;  uint8_t* ref_regs = ref_get_regs();
// 做 memcmp，不用逐字段比。
// ---------------------------------------------------------------------------

// GPR 规模：4 个 32bit 寄存器 = 16 字节（对齐 RegFile.scala）
static constexpr int SEMU_NUM_GPR = 4;
static constexpr int SEMU_GPR_BYTES = SEMU_NUM_GPR * 4;

// 指令 ROM 中「未定义地址」的填充值。
// 0xC0 = op=11 | offset=0000 | rs2=00 → 条件 R[0] != R[0] 恒假，是一条不改任何状态的 NOP。
// 不能填 0x00：0x00 会被译成 add r0,r0,r0，把用作分支比较基准的 r0 翻倍。
static constexpr uint8_t NOP_INSTR = 0xC0;

// ---- difftest REF 接口（供 npc/cpp/nvboard_main.cpp 调用）----

// 装载程序。必须和 chisel 展开 ROM 时用的是同一个文件，否则两边跑的不是同一个程序。
bool ref_load_program(const std::string& program_path);

// 复位状态：寄存器清零、PC 回到程序入口、设备输出寄存器清零
void ref_reset();

// 执行一条指令（与 DUT 的一个时钟周期对应）
void ref_inst_cycle();

// 取 GPR 的字节视图（little-endian，长度 SEMU_GPR_BYTES），可直接与 DUT 的 GPR memcmp
uint8_t* ref_get_regs();

// 取当前 PC / 设备 0 的输出寄存器
uint32_t ref_get_pc();
uint8_t ref_get_dev_out();

// 拨杆开关输入：DUT 的 sw 端口和这里必须喂同一个值
void ref_set_sw(uint8_t v);

```

实现上述接口：

```c
#include "sEMU.h"
#include <fstream>
#include <iostream>
#include <string>

// ---------------------------------------------------------------------------
// sEMU —— sCPU（chisel 实现）的软件参考模型（difftest REF）。
// 规范完全照抄 npc/chisel/src/main/scala/，必须与 RTL 逐周期一致。
// ---------------------------------------------------------------------------

// ---- REF 状态 ----
// GPR：连续的字节数组（little-endian），difftest 直接 memcmp
static uint8_t gpr[SEMU_GPR_BYTES];
// 程序计数器：32bit
static uint32_t pc = 0;
// 设备 0 的输出寄存器（8bit），即数码管显示的值
static uint8_t dev_out = 0;
// 设备 1 的输入值（拨杆开关，8bit）
static uint8_t sw_val = 0;
// 指令 ROM：256 字节
static uint8_t rom[256];

// 32bit 寄存器读写（little-endian）
static inline uint32_t gpr_get(int i) {
    const uint8_t* p = gpr + i * 4;
    return (uint32_t)p[0] | ((uint32_t)p[1] << 8) |
           ((uint32_t)p[2] << 16) | ((uint32_t)p[3] << 24);
}

static inline void gpr_set(int i, uint32_t v) {
    uint8_t* p = gpr + i * 4;
    p[0] = (uint8_t)(v & 0xFF);
    p[1] = (uint8_t)((v >> 8) & 0xFF);
    p[2] = (uint8_t)((v >> 16) & 0xFF);
    p[3] = (uint8_t)((v >> 24) & 0xFF);
}

// 去行内注释（// 或 #）
static std::string strip_comment(const std::string& line) {
    size_t pos = line.find("//");
    if (pos != std::string::npos) return line.substr(0, pos);
    pos = line.find('#');
    if (pos != std::string::npos) return line.substr(0, pos);
    return line;
}

bool ref_load_program(const std::string& program_path) {
    std::ifstream fin(program_path);
    if (!fin.is_open()) {
        std::cerr << "无法打开程序文件: " << program_path << "\n";
        return false;
    }

    // 未定义地址填 NOP（对齐 Memory.scala）
    for (int i = 0; i < 256; i++) rom[i] = NOP_INSTR;

    std::string raw;
    int line_no = 0;

    // 装载指针必须与执行用的 PC 分开：装载结束后 PC 要回到程序入口，
    // 不能停在「最后一条指令的下一条地址」。
    uint8_t addr = 0;
    bool loaded_any = false;

    while (std::getline(fin, raw)) {
        ++line_no;
        std::string line = strip_comment(raw);

        // 去掉首尾空白
        size_t b = line.find_first_not_of(" \t\r\n");
        if (b == std::string::npos) continue;   // 空行
        size_t e = line.find_last_not_of(" \t\r\n");
        line = line.substr(b, e - b + 1);

        if (line[0] == '@') {
            // @地址
            std::string addr_str = line.substr(1);
            try {
                unsigned long a = std::stoul(addr_str, nullptr, 16); // 地址按十六进制
                if (a > 255) {
                    std::cerr << "第 " << line_no << " 行: 地址越界 " << addr_str << "\n";
                    return false;
                }
                addr = static_cast<uint8_t>(a);
            } catch (...) {
                std::cerr << "第 " << line_no << " 行: 非法地址 " << addr_str << "\n";
                return false;
            }
        } else {
            // 指令字节（十六进制）
            try {
                unsigned long val = std::stoul(line, nullptr, 16);
                if (val > 255) {
                    std::cerr << "第 " << line_no << " 行: 指令值越界 " << line << "\n";
                    return false;
                }
                if (!loaded_any) {
                    loaded_any = true;
                    if (addr != 0) {
                        std::cerr << "警告: 程序第一条指令在 0x" << std::hex << (int)addr
                                  << std::dec << "，但 PC 复位值是 0（chisel PC.scala），"
                                  << "两边都只会从 0 开始跑 NOP\n";
                    }
                }
                rom[addr] = static_cast<uint8_t>(val);
                addr = static_cast<uint8_t>(addr + 1);   // 自然回绕（255 -> 0）
            } catch (...) {
                std::cerr << "第 " << line_no << " 行: 非法指令 " << line << "\n";
                return false;
            }
        }
    }

    return true;
}

void ref_reset() {
    for (int i = 0; i < SEMU_GPR_BYTES; i++) gpr[i] = 0;
    dev_out = 0;
    // 复位 PC = 0，和 PC.scala 的 RegInit(0) 完全一致。
    // 所以程序必须放在 0 号地址：否则 RTL 和 REF 都只会从 0 开始跑 NOP。
    pc = 0;
}

void ref_inst_cycle() {
    // ROM 用 PC 的低 8 bit 索引（Top.scala: mem.io.addr := pc.io.pc(7, 0)）
    uint8_t inst = rom[pc & 0xFF];

    // ---- 译码（Controler.scala）----
    uint8_t op     = (inst >> 6) & 3;
    uint8_t rd     = (inst >> 4) & 3;
    uint8_t rs1    = (inst >> 2) & 3;
    uint8_t rs2    = inst & 3;
    uint8_t imm    = inst & 3;                    // LI 立即数
    uint8_t shamt  = ((inst >> 2) & 3) << 1;      // LI 移位量 s << 1
    uint8_t ioDir  = (inst >> 3) & 1;             // 0 = 读设备，1 = 写设备
    uint8_t devIdx = inst & 7;
    uint8_t offset = (inst >> 2) & 0x0F;          // BNE 偏移：instr[5:2]

    // ---- 立即数（ImmGen.scala）----
    uint32_t li_imm = imm;                                        // 零扩展
    int32_t  br_imm = static_cast<int32_t>((offset ^ 0x8) - 0x8); // 4bit 符号扩展

    // 默认顺序执行
    uint32_t next_pc = pc + 1;

    switch (op) {
    case 0: {   // ADD: R[rd] = R[rs1] + R[rs2]（32bit 运算）
        gpr_set(rd, gpr_get(rs1) + gpr_get(rs2));
        break;
    }
    case 1: {   // IO
        if (ioDir) {
            // 写设备：只有设备 0 有输出寄存器（Device.scala）
            if (devIdx == 0) dev_out = static_cast<uint8_t>(gpr_get(rd));
        } else {
            // 读设备 → 写回 R[rd]
            uint8_t rdata = (devIdx == 0) ? dev_out : ((devIdx == 1) ? sw_val : 0);
            gpr_set(rd, rdata);
        }
        break;
    }
    case 2: {   // LI: R[rd] = imm << (s << 1)
        gpr_set(rd, li_imm << shamt);
        break;
    }
    case 3: {   // BNE: if (R[0] != R[rs2]) PC = PC + sext(offset)
        if (gpr_get(0) != gpr_get(rs2)) {
            next_pc = pc + static_cast<uint32_t>(br_imm);   // 32bit 加法，自然回绕
        }
        break;
    }
    }

    pc = next_pc;
}

uint8_t* ref_get_regs() {
    return gpr;
}

uint32_t ref_get_pc() {
    return pc;
}

uint8_t ref_get_dev_out() {
    return dev_out;
}

void ref_set_sw(uint8_t v) {
    sw_val = v;
}
```

```cpp
#include <nvboard.h>
#include "Vtop.h"
#include "Vtop___024root.h"   // --public-flat-rw 暴露的内部信号（PC / 寄存器堆 / 设备输出）

#include "sEMU.h"

static TOP_NAME dut;

// 由 auto_pin_bind.py 生成的 build/auto_bind.cpp 提供，nvboard 的头文件里没声明
void nvboard_bind_all_pins(TOP_NAME* top);

// chisel 展开 ROM 时用的程序文件；REF 必须喂同一个文件。
// 默认从可执行文件位置推导：<npc>/build/top -> <npc>/chisel/src/main/resources/prog.hex
// 运行时推导而不是构建期塞宏，避免换程序后留陈旧路径。
static std::string default_prog_path() {
  char buf[4096];
  ssize_t n = readlink("/proc/self/exe", buf, sizeof(buf) - 1);
  if (n > 0) {
    buf[n] = '\0';
    std::string exe(buf);
    size_t slash = exe.find_last_of('/');
    if (slash != std::string::npos) {
      return exe.substr(0, slash) + "/../chisel/src/main/resources/prog.hex";
    }
  }
  return "chisel/src/main/resources/prog.hex";
}

// ---------------------------------------------------------------------------
// DUT
// ---------------------------------------------------------------------------

static void dut_single_cycle() {
  dut.clock = 0; dut.eval();
  dut.clock = 1; dut.eval();
}

static void dut_reset(int n) {
  dut.reset = 1;
  while (n -- > 0) dut_single_cycle();
  dut.reset = 0;
}

// DUT 的 GPR 字节视图（little-endian）。
//
// 当前 chisel 的 RegFile 是 4 个独立 32bit 寄存器（RegFile.scala），
// 在 verilated model 里是 4 个独立信号、不是连续数组，所以先拷进一块
// 16 字节的 little-endian 缓冲再比。
//
// 以后把 chisel 的 GPR 改成数组式（Mem / Vec），这里换成
//     uint8_t* dut_regs = (uint8_t*)&dut.rootp->...__DOT__Memory;
// 就够了，下面的 check_regs / 打印逻辑都不用动。
static uint8_t dut_gpr_buf[SEMU_GPR_BYTES];

static uint8_t* dut_get_regs() {
  const uint32_t r[SEMU_NUM_GPR] = {
    dut.rootp->top__DOT___rf_io_regs_0,
    dut.rootp->top__DOT___rf_io_regs_1,
    dut.rootp->top__DOT___rf_io_regs_2,
    dut.rootp->top__DOT___rf_io_regs_3,
  };
  for (int i = 0; i < SEMU_NUM_GPR; i++) {
    for (int b = 0; b < 4; b++) {
      dut_gpr_buf[i * 4 + b] = (uint8_t)((r[i] >> (8 * b)) & 0xFF);
    }
  }
  return dut_gpr_buf;
}

// DUT 的 PC（32bit）和设备 0 的输出寄存器
static uint32_t dut_get_pc() {
  return dut.rootp->top__DOT___pc_io_pc;
}

static uint8_t dut_get_dev_out() {
  return dut.rootp->top__DOT___dev_io_out;
}

// ---------------------------------------------------------------------------
// difftest
// ---------------------------------------------------------------------------

// 从 GPR 字节视图里取第 i 个 32bit 寄存器
static uint32_t gpr_get32(const uint8_t* p, int i) {
  const uint8_t* q = p + i * 4;
  return (uint32_t)q[0] | ((uint32_t)q[1] << 8) |
         ((uint32_t)q[2] << 16) | ((uint32_t)q[3] << 24);
}

// 比较两边的 GPR
static int check_regs(const uint8_t* dut_regs, const uint8_t* ref_regs) {
  for (int i = 0; i < SEMU_GPR_BYTES; i++) {
    if (dut_regs[i] != ref_regs[i]) return 1;
  }
  return 0;
}

// fault_pc = 出错那条指令的地址（执行前的 PC）
static void report_diff(uint64_t cycle, uint32_t fault_pc,
                        const uint8_t* dut_regs, const uint8_t* ref_regs,
                        bool gpr_diff, bool pc_diff, bool dev_diff) {
  if (gpr_diff) printf("GPR different\n");
  if (pc_diff)  printf("PC different\n");
  if (dev_diff) printf("dev_out different\n");

  printf("  cycle %llu\n", (unsigned long long)cycle);
  // 出错那条指令：地址 + 指令字节 + 反汇编
  printf("  PC = 0x%08x (%u)  instr = 0x%02x  %s\n",
         fault_pc, fault_pc, ref_get_inst_at(fault_pc),
         ref_disasm_at(fault_pc).c_str());

  for (int i = 0; i < SEMU_NUM_GPR; i++) {
    uint32_t d = gpr_get32(dut_regs, i);
    uint32_t r = gpr_get32(ref_regs, i);
    if (d != r) {
      printf("  R[%d]: dut=0x%08x (%u)  ref=0x%08x (%u)\n", i, d, d, r, r);
    }
  }

  // 执行完这条指令之后，两边各自要去的下一个 PC
  uint32_t dpc = dut_get_pc();
  uint32_t rpc = ref_get_pc();
  printf("  next PC: dut=0x%08x (%u)  ref=0x%08x (%u)\n", dpc, dpc, rpc, rpc);

  if (dev_diff) {
    printf("  dev_out: dut=0x%02x  ref=0x%02x\n",
           dut_get_dev_out(), ref_get_dev_out());
  }
  printf("Simulation stop\n");
  fflush(stdout);
}

// main
// ---------------------------------------------------------------------------

static void usage(const char* prog) {
  fprintf(stderr,
          "Usage: %s [prog.hex] [options]\n"
          "  --difftest       打开 difftest：与 sEMU 参考模型逐周期对拍（默认关闭）\n"
          "  --headless       不开 GUI（CI / 无显示环境用），配合 --difftest\n"
          "  --cycles N       最多跑 N 个周期（默认不限）\n"
          "  --sw N           拨杆开关初值（headless 模式）\n",
          prog);
}

int main(int argc, char* argv[]) {
  std::string prog_path = default_prog_path();
  uint64_t max_cycles = 0;      // 0 = 不限
  bool difftest = false;        // difftest 默认关闭，要用参数打开
  bool headless = false;        // 不开 GUI
  uint8_t sw = 0;
  bool prog_set = false;
  
  // 解析命令行参数
  for (int i = 1; i < argc; i++) {
    std::string opt = argv[i];
    if (opt == "--difftest") {
      difftest = true;
    } else if (opt == "--headless") {
      headless = true;
    } else if (opt == "--cycles" && i + 1 < argc) {
      max_cycles = strtoull(argv[++i], nullptr, 10);
    } else if (opt == "--sw" && i + 1 < argc) {
      sw = (uint8_t)strtoul(argv[++i], nullptr, 0);
    } else if (!prog_set && opt[0] != '-') {
      prog_path = opt;          // 第一个非选项参数 = 程序文件
      prog_set = true;
    } else {
      usage(argv[0]);
      return -1;
    }
  }
  if (headless && max_cycles == 0) max_cycles = 10000;
  
  // ---- REF 侧：只有 difftest 才装载和运行 ----
  if (difftest) {
    if (!ref_load_program(prog_path)) {
      fprintf(stderr, "ref_load_program: load program failed: %s\n", prog_path.c_str());
      return -1;
    }
    ref_reset();
    ref_set_sw(sw);
    printf("difftest start: program=%s\n", prog_path.c_str());
  }

  // ---- DUT 侧准备 ----
  if (headless) {
    dut.sw = sw;
  } else {
    nvboard_bind_all_pins(&dut);
    nvboard_init();
  }

  dut_reset(10);

  // -------------------------------------------------------------------------
  // 主循环：处理器和 REF 同步跑，每个周期比一次状态
  // -------------------------------------------------------------------------
  uint64_t cycle = 0;
  int is_diff = 0;

  while (!is_diff) {
    if (!headless) nvboard_update();   // 刷新 sw 输入并重绘
    
    // 两个模型走同一个 sw 输入
    if (difftest) ref_set_sw(headless ? sw : dut.sw);

    // 执行前的 PC = 本周期要执行的那条指令的地址（出错时用得上）
    uint32_t fault_pc = difftest ? dut_get_pc() : 0;
    
    dut_single_cycle();
    if (difftest) ref_inst_cycle();
    cycle++;

    if (difftest) {
      uint8_t *dut_regs = dut_get_regs();
      uint8_t *ref_regs = ref_get_regs();

      bool gpr_diff = check_regs(dut_regs, ref_regs);
      bool pc_diff  = dut_get_pc() != ref_get_pc();
      bool dev_diff = dut_get_dev_out() != ref_get_dev_out();
      if (gpr_diff || pc_diff || dev_diff) {
        report_diff(cycle, fault_pc, dut_regs, ref_regs, gpr_diff, pc_diff, dev_diff);
        is_diff = 1;
        break;
      }
    }

    if (max_cycles != 0 && cycle >= max_cycles) break;
  }
  
  if (difftest && !is_diff) {
    printf("difftest passed: %llu cycles, GPR/PC/dev_out all matched\n",
           (unsigned long long)cycle);
  }

  if (!headless) {
    // 让板子把最后一帧画出来
    nvboard_update();
  }
  return is_diff ? 1 : 0;
}
```
