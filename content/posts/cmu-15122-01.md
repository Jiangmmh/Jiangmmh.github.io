# Lecture1笔记
> 本节课的主题：**在开发软件系统时，如何实现从直觉调试到形式化证明**？

在软件开发中，我们经常遇到这样的场景：编写了一段看似精妙的算法，测试了几个样例都通过了，但在某种特定输入下程序却悄悄返回了错误答案，或者陷入死循环。

传统的方法是加 `printf` 或打断点一步步跟踪（Operational Reasoning）。但对于复杂的循环逻辑，单靠“脑补执行过程”不仅效率低下，而且极易遗漏边缘情况。

这是 CMU 15-122（*Principles of Imperative Computation*）的核心思想。下面以一个经典的**快速幂算法（Fast Exponentiation）**为例，展示如何通过**契约式编程（Contracts）**与**循环不变式（Loop Invariants）**，从原理上证明算法的正确性，并精准推导出代码中的隐藏 Bug。


## 1. 问题背景：一个看似正确的快速幂实现

假设我们需要实现一个计算 $x^y$ 的快速幂函数 $f(x, y)$（其中 $y \ge 0$）。

通过不断拆分指数，我们可以在 $O(\log y)$ 的时间复杂度内完成计算。下面是最初的代码实现：

```c
// Specification function!
int POW(int b, int e)
//@requires e >= 0;
{
  if (e == 0) return 1;
  return POW(b, e-1) * b;
}

// 计算 x 的 y 次方
int f(int x, int y)
//@requires y >= 0;
//@ensures \result == POW(x, y);
{
    int b = x;
    int e = y;
    int r = 1;

    while (e > 1) {
        if (e % 2 == 1) {
            r = b * r;
        }
        b = b * b;
        e = e / 2;
    }

    return r * b;
}
```

### 契约（Contracts）说明：
* `@requires y >= 0;`：**前置条件（Precondition）**，调用者必须保证 $y \ge 0$。
* `@ensures \result == POW(x, y);`：**后置条件（Postcondition）**，函数必须保证返回结果等于数学上的 $x^y$。

### 运行测试：
如果我们测试 `f(2, 8)`：
* 循环前：$b=2, e=8, r=1$
* 经过若干轮：$b=256, e=1, r=1$
* 退出循环，返回 `r * b = 1 * 256 = 256`。结果完全正确（$2^8 = 256$）。

但是，这段代码真的**严谨正确**吗？如果我们传入 `f(2, 0)` 呢？


## 2. 为什么需要抽象？引入循环不变式（Loop Invariants）

在追踪代码时，变量的值随着每轮循环不断变化。**人类的大脑并不擅长模拟高精度的状态转移**。为了理解复杂的循环，我们需要对循环进行**抽象（Abstraction）**。

正如前置/后置条件是对“函数”的抽象一样，**循环不变式（Loop Invariant）** 是对“循环”的抽象。

> **循环不变式（Loop Invariant）** ：在循环测试条件（Loop Guard）之前，每一次迭代都必然保持为 `true` 的布尔表达式。

### 如何寻找循环不变式？
通过对变量在每轮迭代前的状态进行追踪：
以 `f(2, 7)` 为例：
* 初始：$b=2, e=7, r=1 \implies r \cdot b^e = 1 \cdot 2^7 = 128 = x^y$
* 第 1 轮后：$b=4, e=3, r=2 \implies r \cdot b^e = 2 \cdot 4^3 = 128 = x^y$
* 第 2 轮后：$b=16, e=1, r=8 \implies r \cdot b^e = 8 \cdot 16^1 = 128 = x^y$

我们发现了一个关键的不变特征：在循环的任何阶段，项 $r \cdot b^e$ 的值始终等于初始的 $x^y$！

因此，我们可以写出两个重要的循环不变式：
1. `//@loop_invariant e >= 0;`（保证指数非负，使指数运算安全）
2. `//@loop_invariant POW(b, e) * r == POW(x, y);`（核心数学约束）

加入不变式后的代码如下：

```c
int f(int x, int y)
//@requires y >= 0;
//@ensures \result == POW(x, y);
{
    int b = x;
    int e = y;
    int r = 1;

    while (e > 1)
    //@loop_invariant e >= 0;
    //@loop_invariant POW(b, e) * r == POW(x, y);
    {
        if (e % 2 == 1) {
            r = b * r;
        }
        b = b * b;
        e = e / 2;
    }

    return r * b;
}
```


## 3. 证明循环不变式的有效性（INIT & PRES）

在将候选的不变式写入代码前，我们不能仅靠有限次测试，而是需要通过**归纳逻辑（Point-to Reasoning）** 严密证明其有效性。证明分为两个步骤：**初始性（INIT）**与**保持性（PRES）**。

我们以核心不变式 `POW(b, e) * r == POW(x, y)` 为例：

### ① 初始性（Initialization / INIT）
**目标**：证明在第一次测试循环条件（Loop Guard）之前，不变式就已经成立。

* **推导过程**：
  根据循环前的变量初始化代码：
  $$b = x, \quad e = y, \quad r = 1$$
  将这些初始值代入不变式左端：
  $$\text{POW}(b, e) \cdot r = \text{POW}(x, y) \cdot 1 = \text{POW}(x, y)$$
* **结论**：等式右端同样为 $\text{POW}(x, y)$，初始性成立（INIT $\checkmark$）。

### ② 保持性（Preservation / PRES）
**目标**：假设在某次迭代开始时不变式成立（即 $\text{POW}(b, e) \cdot r = \text{POW}(x, y)$），证明在该次迭代结束时（记新变量值为 $b', e', r'$），不变式依然成立（即 $\text{POW}(b', e') \cdot r' = \text{POW}(x, y)$）。

因为循环体内对 $e$ 的奇偶性进行了条件判断，我们分为两种情况推导：

#### 情况 A：$e$ 为奇数（`e % 2 == 1`）
1. 设 $e = 2n + 1$（其中 $n \ge 0$ 为整数）。
2. 根据循环体代码执行更新：
   * $r' = b \cdot r$ （执行 `r = b * r`）
   * $b' = b^2$ （执行 `b = b * b`）
   * $e' = e / 2 = (2n + 1) / 2 = n$ （C 语言整除，执行 `e = e / 2`）
3. 计算迭代后的表达式 $\text{POW}(b', e') \cdot r'$：
   $$
   \begin{aligned}
   \text{POW}(b', e') \cdot r' &= (b^2)^n \cdot (b \cdot r) \\
   &= b^{2n} \cdot b \cdot r \\
   &= b^{2n+1} \cdot r \\
   &= b^e \cdot r
   \end{aligned}
   $$
4. 根据假设 $b^e \cdot r = \text{POW}(x, y)$，可得 $\text{POW}(b', e') \cdot r' = \text{POW}(x, y)$。

#### 情况 B：$e$ 为偶数（`e % 2 == 0`）
1. 设 $e = 2n$（其中 $n \ge 0$ 为整数）。
2. 根据循环体代码执行更新：
   * $r' = r$ （不满足 `if` 条件，保持不变）
   * $b' = b^2$ （执行 `b = b * b`）
   * $e' = e / 2 = (2n) / 2 = n$ （执行 `e = e / 2`）
3. 计算迭代后的表达式 $\text{POW}(b', e') \cdot r'$：
   $$
   \begin{aligned}
   \text{POW}(b', e') \cdot r' &= (b^2)^n \cdot r \\
   &= b^{2n} \cdot r \\
   &= b^e \cdot r
   \end{aligned}
   $$
4. 同样根据假设，可得 $\text{POW}(b', e') \cdot r' = \text{POW}(x, y)$。

**结论**：无论 $e$ 是奇数还是偶数，迭代结束时都有 $\text{POW}(b', e') \cdot r' = \text{POW}(x, y)$，保持性成立（PRES $\checkmark$）。

通过 INIT 与 PRES 的双重证明，我们确认了 `POW(b,e) * r == POW(x, y)` 是一个**绝对真实且有效**的循环不变式。


## 4. 基于证明的调试（Proof-Directed Debugging）：发现与定位 Bug

有了经过验证的循环不变式，我们甚至**不需要运行代码**，就能指出问题所在。

### 分析退出循环时的状态：
当程序退出 `while (e > 1)` 循环时，我们已知两件事：
1. **Loop Guard 为假**：$e \le 1$
2. **Loop Invariants 必为真**：$e \ge 0$ 且 $b^e \cdot r = x^y$

结合 $e \le 1$ 和 $e \ge 0$，推导出在退出循环时，$e$ 只可能有两种取值：**$e = 1$ 或 $e = 0$**。

带入核心不变式分析：
* **情况 A：若 $e = 1$**
  $$x^y = b^1 \cdot r = r \cdot b$$
  此时函数的返回值是 `return r * b;`，与 $x^y$ 完全吻合！正确。

* **情况 B：若 $e = 0$**
  $$x^y = b^0 \cdot r = 1 \cdot r = r$$
  此时 $x^y$ 的实际值应该是 $r$，但函数却依然返回了 `r * b`！**Bug 找到了！**

### 为什么 $e = 0$ 会发生？
当输入 $y = 0$ 时，初始 $e = y = 0$。循环条件 `e > 1` 直接为假，循环一次都不执行，直接跳到 `return r * b;`，导致 `f(x, 0)` 返回了 $1 \cdot x = x$（正确答案应为 $1$）。


## 5. 优雅的解决方案

知道了根源在于 $e=0$ 的错误处理，常见的解决思路有几种：

* **方案一：加特例判断 `if (y == 0) return 1;`**
  * *评价*：补丁代码，增加了条件分支，不够优雅。
* **方案二：修改循环条件为 `while (e > 0)`**
  * *评价*：**完美方案！**

如果我们把 Guard 改为 `while (e > 0)`：
1. 当循环结束时，Guard 为假 $\implies e \le 0$。
2. 结合不变式 $e \ge 0 \implies$ **退出循环时必有 $e = 0$**。
3. 将 $e = 0$ 带入不变式：$x^y = b^0 \cdot r = r$。
4. 此时，函数只需统一返回 `r` 即可，**无需任何特例判断**！

### 最终重构后的代码：

```c
int f(int x, int y)
//@requires y >= 0;
//@ensures \result == POW(x, y);
{
    int b = x;
    int e = y;
    int r = 1;

    while (e > 0)
    //@loop_invariant e >= 0;
    //@loop_invariant POW(b, e) * r == POW(x, y);
    {
        if (e % 2 == 1) {
            r = b * r;
        }
        b = b * b;
        e = e / 2;
    }

    //@assert e == 0; // 明确断言：此时 e 一定为 0
    return r;
}
```

## 6. 补充：算法终止性证明（Termination）

一个函数要彻底达到**正确性（Correctness）**，除了证明“如果它返回，结果一定对”之外，还必须证明 **“它一定会终止（不会死循环）”** 。

对于上述代码，终止性证明非常直观：
1. 变界量（Variant metric）：$e$ 是一个整数。
2. 下界（Lower bound）：循环不变式保证 $e \ge 0$。
3. 严格递减（Strict decrease）：在每轮循环中，$e' = e / 2$。由于在循环内部 $e > 0$，所以 $e / 2$ 必然严格小于 $e$。
4. 结论：$e$ 从有限正整数开始，每轮严格递减且有下界 0，因此循环必然在有限步内终止。

## 总结

在没有使用 Formal Reasoning（形式化推导）之前，我们可能需要通过死记硬背或试错来修正边界条件；而利用 **Loop Invariants（循环不变式）**：

1. 我们把复杂的动态循环转化为了静态的状态约束；
2. 退出循环时的逻辑推导直接暴露出代码缺陷；
3. 将 $e=0$ 从原本的漏洞转化为了统一的终止条件，写出了零特例判断的高质量代码。

这种推导思维不仅适用于 C0/C 语言，在你使用任何现代语言撰写复杂业务逻辑或底座算法时，都能提供极其扎实的逻辑保障。

```c
#use <conio>

int fact_spec(int n)
//@requires n >= 0;
{
  if (n == 0) return 1;
  else return n * fact_spec(n-1);
}

int factorial(int n)
//@requires n >= 0;
//@ensures \result == fact_spec(n);
{
  int total = 1;
  int count = 0;
  while (count < n)
    //@loop_invariant 0 <= count && count <= n;
    //@loop_invariant total == fact_spec(count);
    {
      count = count + 1;
      total = total * count;
    }
  return total;
}

int main()
{
  for (int i = 0; i < 10; i++)
    {
      printint(factorial(i));
      print("\n");
    }
  print("Returning from main\n");
  return 0;
}

```
