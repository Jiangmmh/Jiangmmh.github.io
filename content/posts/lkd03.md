# 一、进程是什么？

进程（Process）是程序执行过程中的一个实例。

程序（Program）是存储在磁盘上的静态指令和数据，而进程是程序运行时的动态实体。一个程序可以对应多个进程；一个进程也不只是代码本身，它还拥有自己的运行状态、虚拟地址空间、打开的文件、信号处理信息以及处理器上下文等资源。

从操作系统的角度看，进程是资源分配和管理的重要单位，也是内核进行调度和管理的基本对象。

一个进程通常包含以下几个方面：

- **代码和数据**：程序的指令以及全局变量、静态变量等。
- **虚拟地址空间**：进程可以访问的虚拟内存范围。
- **打开的文件**：进程持有的文件描述符及其对应的内核对象。
- **处理器上下文**：程序计数器、寄存器、栈指针等运行状态。
- **进程控制信息**：进程 ID、父进程、状态、调度信息等。

需要注意：**进程是内核管理的实体，而不是简单的一段代码。**

# 二、进程描述符与 task_struct

## 2.1 什么是进程描述符？

内核需要一种数据结构来描述和管理进程。

Linux 使用 `struct task_struct` 表示进程描述符（Process Descriptor）。它定义在：

```c
include/linux/sched.h
```

每一个进程都有一个对应的 `task_struct`，内核通过它获取进程的状态、调度信息、内存管理信息以及其他资源。

可以把 `task_struct` 理解为内核管理进程的核心控制块，类似于其他操作系统中的 PCB（Process Control Block）。

Linux 的进程描述符包含大量信息，常见字段如下：

| 字段 | 作用 |
|---|---|
| `state` | 进程当前状态 |
| `pid` | 进程 ID |
| `tgid` | 线程组 ID |
| `flags` | 进程标志 |
| `prio` | 动态优先级 |
| `static_prio` | 静态优先级 |
| `normal_prio` | 普通优先级 |
| `policy` | 调度策略 |
| `mm` | 进程内存描述符 |
| `active_mm` | 当前活动地址空间 |
| `parent` | 父进程 |
| `children` | 子进程链表 |
| `real_parent` | 实际父进程 |
| `files` | 打开的文件信息 |
| `fs` | 文件系统相关信息 |
| `signal` | 信号相关信息 |
| `sighand` | 信号处理信息 |
| `tasks` | 进程任务链表节点 |

注意：这里列出的是帮助理解的代表性字段，不意味着不同 Linux 内核版本中的字段布局完全一致。Linux 内核数据结构会随着版本不断演进。

## 2.2 进程描述符与内核栈

每个进程除了 `task_struct`，还需要内核栈（Kernel Stack）。

用户进程通过系统调用、中断或异常进入内核时，CPU 需要切换到内核态执行代码。此时内核必须拥有独立的执行栈，用于保存函数调用过程中的局部变量、返回地址和寄存器现场等信息。

因此，每个任务都需要与之关联的内核栈。

在传统的 Linux 内核实现中，`task_struct` 与内核栈的内存布局关系比较紧密；在现代实现中，二者的分配和关联方式已经发生变化。

理解时要区分：

- `task_struct`：描述任务的管理信息。
- 内核栈：保存任务在内核态执行时的调用栈和相关上下文。
- 用户栈：进程在用户态执行时使用的栈，属于用户虚拟地址空间。

它们承担不同职责，不能混为一谈。

## 2.3 通过 current 获取当前进程

内核代码经常需要获取当前正在运行的进程。

Linux 提供 `current` 宏来访问当前任务的 `task_struct`。

例如：

```c
printk("current pid = %d\n", current->pid);
```

不同体系结构可能采用不同的实现方式。

在一些体系结构中，内核可以通过当前任务的内核栈地址计算出 `task_struct` 的位置；其他体系结构则可能使用专门的寄存器或其他机制保存当前任务指针。

理解重点：

**`current` 并不是通过遍历进程链表寻找当前进程，而是通过体系结构相关的机制快速获得当前任务。**

这也是内核代码能够频繁使用 `current` 的原因。

## 2.4 进程描述符的分配

当创建一个新进程时，内核需要为其分配 `task_struct`。

在书中介绍的 Linux 内核实现中，进程描述符的分配与内核栈分配存在紧密联系。

传统实现会将 `thread_info` 放置在内核栈底部附近，并通过它关联对应的 `task_struct`。

```c
struct thread_info {
    struct task_struct *task;
    /* 其他线程相关信息 */
};
```

这里需要注意，`thread_info` 并不等同于 `task_struct`：

- `task_struct` 保存进程管理所需的大量信息。
- `thread_info` 保存与底层体系结构和线程执行相关的信息。

随着内核的发展，`thread_info` 的布局和分配方式也发生过变化。因此，阅读具体内核源码时，应以目标版本为准。

# 三、进程状态（Process State）

进程在生命周期中会经历不同的状态。

Linux 使用状态字段描述进程当前处于什么状态。进程状态是调度器判断一个任务能否运行的重要依据。

## 3.1 常见进程状态

### TASK_RUNNING

表示进程处于可运行状态。

它有两种可能：

1. 正在 CPU 上运行。
2. 已经具备运行条件，正在运行队列中等待 CPU。

因此，`TASK_RUNNING` 并不意味着进程此刻一定正在 CPU 上执行。

### TASK_INTERRUPTIBLE

可中断睡眠状态。

进程等待某个事件发生时，通常会进入该状态。

例如：

- 等待用户输入。
- 等待某个 I/O 操作完成。
- 等待某个内核事件或条件满足。

当等待的条件满足，或者进程收到符合条件的信号时，进程可以被唤醒。

### TASK_UNINTERRUPTIBLE

不可中断睡眠状态。

进程等待某些事件时进入该状态。在通常情况下，信号不会使其提前结束睡眠。

典型场景是等待某些必须完成的内核操作。

在 `ps` 命令中，这种状态通常显示为 `D`。

需要注意：不可中断睡眠不意味着进程永远不会被唤醒。它仍然会在等待条件满足后恢复运行。

### __TASK_STOPPED

进程被停止。

例如，进程收到 `SIGSTOP` 信号后，可以进入停止状态，等待后续的 `SIGCONT` 信号恢复执行。

### __TASK_TRACED

进程正在被调试器或跟踪机制控制。

例如，使用 `ptrace` 调试进程时，目标进程可能进入该状态，等待调试器进一步操作。

## 3.2 进程状态转换

可以将进程状态简化为以下关系：

```text
                  被调度执行
        +----------------------------+
        |                            v
   TASK_RUNNING <--------------- CPU 执行
        |
        | 等待事件
        v
 TASK_INTERRUPTIBLE
        |
        | 事件发生 / 信号唤醒
        v
   TASK_RUNNING


   TASK_RUNNING
        |
        | 等待不可中断事件
        v
 TASK_UNINTERRUPTIBLE
        |
        | 等待条件满足
        v
   TASK_RUNNING


   TASK_RUNNING
        |
        | SIGSTOP / 调试跟踪
        v
 TASK_STOPPED / TASK_TRACED
        |
        | 恢复执行
        v
   TASK_RUNNING
```

上图是概念模型，并没有涵盖所有状态和转换细节。

## 3.3 运行状态与退出状态

除了上述状态，进程生命周期中还涉及退出状态。

常见的退出相关状态包括：

- `EXIT_ZOMBIE`：进程已经退出，但父进程尚未通过等待机制回收其退出信息。
- `EXIT_DEAD`：进程正在被最终释放。

僵尸进程（Zombie Process）是一个非常重要的概念。

进程调用 `exit()` 后，内核会释放它的大部分资源，但仍然需要保留一些信息，例如退出码，以便父进程通过 `wait()` 或 `waitpid()` 获取。

因此，进程不能立即彻底销毁，而是暂时保留进程描述符等必要信息。

父进程调用等待系统调用后，内核才可以最终回收该进程。

**重点：僵尸进程已经不再执行，但仍然占用少量内核进程管理资源。**

如果父进程长期不回收子进程，就可能积累大量僵尸进程。

# 四、进程上下文（Process Context）

当内核执行某个进程的代码时，就处于该进程的上下文中。

进程上下文主要包含：

1. 用户地址空间。
2. 进程内核栈。
3. 进程描述符。
4. 处理器寄存器和执行现场。

进程上下文是理解系统调用、中断和进程切换的基础。

## 4.1 用户态与内核态

用户进程执行时，CPU 通常处于用户态。

当发生系统调用、异常或中断时，CPU 可能进入内核态执行相应的内核代码。

例如：

```c
read(fd, buf, size);
```

用户程序调用 `read()` 后，会通过系统调用机制进入内核，执行相应的文件读取逻辑。

此时虽然 CPU 已经处于内核态，但仍然是在当前进程的上下文中执行。

这意味着：

- 当前任务仍然是原来的进程。
- 内核可以通过 `current` 获取该进程。
- 内核代码可以访问该进程的相关资源。

## 4.2 进程上下文与中断上下文

需要区分进程上下文和中断上下文。

**进程上下文：**

内核代表某个进程执行代码，例如系统调用处理过程。

进程上下文通常允许睡眠和调度，但具体是否允许还取决于锁、原子上下文等约束。

**中断上下文：**

CPU 因硬件中断进入内核执行中断处理程序。

中断处理程序并不是代表某个普通进程主动发起操作，因此不能像普通进程上下文一样随意睡眠。

例如，中断处理程序中不能直接执行可能阻塞当前执行流的操作。

这是因为中断上下文没有一个可以安全地暂停并等待事件的普通进程执行语义。

| 对比 | 进程上下文 | 中断上下文 |
|---|---|---|
| 触发来源 | 系统调用、内核线程等 | 硬件中断等 |
| 是否关联当前任务 | 是 | 中断发生时可能打断某个任务 |
| 是否允许睡眠 | 满足条件时可以 | 通常不允许 |
| 是否可以被调度 | 可以 | 不能像普通进程一样主动阻塞等待调度 |
| 典型工作 | 文件读写、系统调用 | 网卡中断、定时器中断 |

理解这一点对于后续学习中断处理、下半部、内核同步非常重要。

# 五、进程家族树（Process Family Tree）

Linux 中的进程并不是孤立存在的，而是通过父子关系组织起来的。

每个进程通常都有一个父进程，可以创建多个子进程。

内核通过 `task_struct` 中的相关字段维护这些关系。

例如：

```c
struct task_struct {
    struct task_struct *parent;
    struct list_head children;
    struct list_head sibling;
};
```

其中：

- `parent`：指向父进程。
- `children`：维护当前进程的子进程链表。
- `sibling`：将当前进程链接到父进程的子进程链表中。

这些字段展示了 Linux 如何维护进程之间的亲缘关系。

## 5.1 init 进程

Linux 启动过程中，内核会创建初始进程。

传统上，PID 为 1 的用户态初始化进程通常是 `init`，现代 Linux 系统中常见的是 systemd。

它负责系统初始化，并承担孤儿进程重新托管等职责。

## 5.2 孤儿进程

如果父进程先于子进程退出，那么仍在运行的子进程就成为孤儿进程。

Linux 会将孤儿进程重新托管给合适的进程，通常是 init 或相应的子收割进程。

这样可以确保子进程最终退出时，仍然有进程能够回收它的退出状态。

## 5.3 僵尸进程与孤儿进程的区别

这两个概念很容易混淆：

| 概念 | 含义 |
|---|---|
| 孤儿进程 | 父进程已经退出，但子进程仍在运行 |
| 僵尸进程 | 子进程已经退出，但退出信息尚未被父进程回收 |

孤儿进程不一定是问题，系统会为其重新安排父进程。

僵尸进程则意味着退出信息尚未被回收，长期积累可能消耗进程管理资源。

# 六、进程创建（Process Creation）

Linux 中，进程创建主要涉及：

- `fork()`
- `vfork()`
- `clone()`
- `exec()` 系列函数

其中，`fork()` 和 `exec()` 是理解 Unix/Linux 进程模型的关键。

## 6.1 fork()

`fork()` 用于创建一个新的子进程。

调用 `fork()` 后，原进程称为父进程，新创建的进程称为子进程。

```c
pid_t pid = fork();

if (pid < 0) {
    perror("fork");
} else if (pid == 0) {
    // 子进程
    printf("child process\n");
} else {
    // 父进程
    printf("parent process, child pid = %d\n", pid);
}
```

`fork()` 的返回值：

- 小于 0：创建失败。
- 等于 0：当前执行流位于子进程。
- 大于 0：当前执行流位于父进程，返回值是子进程 PID。

调用 `fork()` 后，父子进程都从 `fork()` 返回位置继续执行，但拥有不同的执行上下文。

## 6.2 fork 的资源复制

从语义上看，`fork()` 创建的子进程拥有父进程资源的副本。

例如：

- 虚拟地址空间。
- 文件描述符。
- 信号处理设置。
- 进程相关属性。

但这并不意味着内核会立即将父进程的所有物理内存完整复制一遍。

如果每次 `fork()` 都完整复制整个地址空间，那么创建进程的成本会非常高。

Linux 使用写时复制（Copy-On-Write，COW）优化这一过程。

## 6.3 Copy-On-Write（写时复制）

COW 是 `fork()` 实现中的重要优化。

其核心思想：

**父子进程最初共享相同的物理内存页面，只有当某一方尝试修改页面时，内核才真正复制对应页面。**

可以将过程分为三个阶段。

### 阶段一：创建子进程

父进程调用 `fork()`。

内核为子进程创建进程描述符和相关资源，并建立子进程的地址空间映射。

对于可以共享的内存页面，父子进程的页表可以映射到相同的物理页面。

### 阶段二：设置写保护

为了防止父子进程直接修改共享页面，内核会将相关页面设置为只读或采用相应的 COW 标记机制。

父子进程仍然可以读取这些页面。

### 阶段三：发生写操作

当父进程或子进程尝试写入共享页面时，会触发缺页异常。

内核识别出这是一个 COW 场景后：

1. 分配新的物理页面。
2. 将原页面内容复制到新页面。
3. 更新当前进程的页表映射。
4. 将新页面设置为可写。
5. 重新执行触发异常的指令。

此后，父子进程就可以分别修改自己的页面，不再互相影响。

示意：

```text
fork() 之前：

父进程页表
    |
    v
物理页面 A


fork() 之后：

父进程页表 ----+
              |
              v
          物理页面 A
              ^
              |
子进程页表 ----+


子进程尝试写入：

父进程页表 ------> 物理页面 A

子进程页表 ------> 物理页面 B
                       ^
                       |
                  A 的内容副本
```

COW 带来的好处：

- 避免不必要的物理内存复制。
- 降低 `fork()` 的执行开销。
- 减少进程创建时的内存消耗。

需要注意，COW 并不意味着 `fork()` 完全没有成本。内核仍然需要创建进程相关的数据结构、建立页表映射，并进行必要的引用计数和权限处理。

**进一步理解：COW 与缺页异常密切相关。** 后续学习 Linux 内存管理时，可以结合 `do_wp_page()` 等历史版本中的缺页处理路径，理解写保护缺页如何触发页面复制。具体函数名称和实现会随内核版本变化。

## 6.4 fork 的内核实现

从内核实现角度看，进程创建并不是简单地复制一个 `task_struct`。

书中所介绍的内核实现中，核心路径可以概括为：

```text
用户态 fork()
      |
      v
系统调用入口
      |
      v
do_fork()
      |
      v
copy_process()
      |
      +---- 复制进程描述符
      |
      +---- 分配内核栈
      |
      +---- 复制或共享进程资源
      |
      +---- 建立父子关系
      |
      +---- 初始化调度相关信息
      |
      v
唤醒并调度子进程
```

其中，`copy_process()` 是创建新进程的关键函数。

它负责准备新任务所需的各项数据结构，并根据 `clone` 标志决定哪些资源需要复制，哪些资源可以共享。

注意：这里的 `do_fork()`、`copy_process()` 是书中对应历史内核实现的重要函数。阅读现代 Linux 内核源码时，系统调用入口和创建任务的函数组织可能已经变化，不应假设函数名和调用链完全相同。

## 6.5 vfork()

`vfork()` 与 `fork()` 类似，也用于创建子进程，但它的行为有一个重要区别：

**在子进程调用 `exec()` 或退出之前，父进程会被挂起。**

传统 `vfork()` 的语义中，父子进程在这段时间内共享地址空间，因此子进程不能像普通独立进程那样随意修改父进程的数据。

例如：

```c
pid_t pid = vfork();

if (pid == 0) {
    execve("/bin/ls", argv, envp);
    _exit(127);
} else {
    // 父进程在子进程 exec 或退出后继续执行
}
```

`vfork()` 的设计目的，是降低创建子进程后立即执行 `exec()` 时的开销。

但它对父子进程执行顺序和地址空间访问有严格限制，错误使用可能导致未定义行为或数据破坏。

现代程序一般优先使用 `fork()`，或者根据具体需求使用更合适的进程创建接口。

## 6.6 fork、vfork 与 exec 的区别

| 接口 | 主要作用 | 地址空间行为 |
|---|---|---|
| `fork()` | 创建子进程 | 逻辑上获得父进程地址空间的副本，通常通过 COW 实现 |
| `vfork()` | 创建子进程并优化随后执行新程序的场景 | 子进程暂时与父进程共享地址空间，父进程挂起 |
| `exec()` | 用新程序替换当前进程的程序映像 | 替换当前进程的地址空间，不创建新进程 |

这三个接口经常配合使用：

```text
父进程
  |
  | fork()
  v
子进程
  |
  | exec()
  v
执行新程序
```

# 七、Linux 中的线程（Threads）

## 7.1 什么是线程？

线程是进程内部的执行单元。

一个进程可以包含多个线程，这些线程共享进程的大部分资源，但各自拥有独立的执行上下文。

同一进程中的线程通常共享：

- 虚拟地址空间。
- 全局变量和堆内存。
- 打开的文件描述符。
- 信号处理相关资源（具体语义取决于资源类型）。

每个线程则拥有自己的：

- 程序计数器。
- CPU 寄存器上下文。
- 栈。
- 线程局部存储。
- 调度状态。

例如：

```text
进程
 |
 +-- 线程 A
 |     +-- 独立寄存器上下文
 |     +-- 独立栈
 |
 +-- 线程 B
 |     +-- 独立寄存器上下文
 |     +-- 独立栈
 |
 +-- 线程 C
       +-- 独立寄存器上下文
       +-- 独立栈

所有线程共享：
    - 虚拟地址空间
    - 全局数据
    - 堆
    - 文件描述符等资源
```

## 7.2 Linux 如何实现线程？

Linux 内核并没有将进程和线程完全设计成两套不同的实体。

在 Linux 中，**线程也是一个任务（task）**。

内核通过 `task_struct` 描述任务。无论是传统意义上的进程，还是线程，内核都使用相同的基本任务管理机制。

线程与普通进程的重要区别在于资源共享关系。

例如：

- 普通 `fork()` 创建的子进程拥有独立的地址空间。
- 使用合适的 `clone()` 标志创建的线程，可以共享父任务的地址空间、文件系统信息、文件描述符表等资源。

因此，Linux 线程本质上是共享特定资源的一组任务。

## 7.3 clone()

Linux 提供 `clone()` 系统调用，用于创建新的任务。

`clone()` 可以通过不同的标志控制父子任务之间的资源共享关系。

常见标志：

| 标志 | 作用 |
|---|---|
| `CLONE_VM` | 共享地址空间 |
| `CLONE_FS` | 共享文件系统相关信息 |
| `CLONE_FILES` | 共享打开文件描述符表 |
| `CLONE_SIGHAND` | 共享信号处理程序 |
| `CLONE_THREAD` | 加入同一个线程组 |
| `CLONE_PARENT` | 使用与调用者相同的父进程关系 |

例如，创建线程时通常需要共享地址空间，并根据线程模型共享其他资源。

可以看到，Linux 的线程机制非常灵活：通过不同的共享标志，内核可以创建具有不同资源共享关系的任务。

## 7.4 POSIX 线程与 Linux 内核线程模型

用户态通常使用 POSIX Threads（pthread）接口创建线程。

例如：

```c
#include <pthread.h>
#include <stdio.h>

void *worker(void *arg)
{
    printf("worker thread\n");
    return NULL;
}

int main(void)
{
    pthread_t tid;

    pthread_create(&tid, NULL, worker, NULL);
    pthread_join(tid, NULL);

    return 0;
}
```

`pthread_create()` 是用户态线程库提供的接口。

在 Linux 上，现代线程库通常通过底层任务创建机制实现线程创建。

这里需要区分：

- pthread 是用户态提供的线程编程接口。
- `clone()` 是 Linux 提供的底层任务创建机制。
- `task_struct` 是内核管理任务的基本数据结构。

不要把 pthread 对象与 `task_struct` 直接等同起来。

## 7.5 线程组与 PID/TID

Linux 中，每个任务都有自己的任务 ID。

对于线程组：

- TGID：线程组 ID，通常对应用户通常所说的进程 ID。
- TID：具体线程的任务 ID。

同一个线程组中的多个线程拥有相同的 TGID，但各自拥有不同的 TID。

例如：

```text
进程（TGID = 1000）

线程 A：TID = 1000
线程 B：TID = 1001
线程 C：TID = 1002
```

在用户态，`getpid()` 通常返回线程组 ID；`gettid()` 返回当前线程的 TID。

这种设计使得内核既可以统一管理线程组，又能够单独调度每一个线程。

# 八、内核线程（Kernel Threads）

内核线程是由内核创建并运行的任务。

它与普通用户进程不同：

- 内核线程执行内核代码。
- 不运行普通用户态程序。
- 通常不拥有独立的用户地址空间。
- 可以参与内核调度。

常见内核线程包括：

- 内核工作线程。
- 内存回收相关线程。
- 块设备和其他子系统相关线程。

在 Linux 中，可以通过 `ps` 查看系统中的内核线程，例如：

```bash
ps -eLf
```

或者：

```bash
ps -ef
```

部分内核线程在进程列表中会显示为方括号形式，例如：

```text
[kthreadd]
[kworker/0:1]
[kswapd0]
```

## 8.1 内核线程与普通进程的区别

| 对比 | 普通用户进程 | 内核线程 |
|---|---|---|
| 执行代码 | 用户程序和内核代码 | 内核代码 |
| 用户地址空间 | 通常拥有 | 通常没有独立用户地址空间 |
| 内核态执行 | 系统调用时进入 | 始终执行内核代码 |
| 调度 | 由内核调度器管理 | 由内核调度器管理 |

注意：内核线程同样具有 `task_struct`，也会被调度器调度。它并不是绕过调度器运行的特殊执行流。

## 8.2 内核线程的作用

内核中有许多工作不适合直接在中断处理程序或其他原子上下文中完成。

例如：

- 需要睡眠等待的操作。
- 可以延迟执行的后台工作。
- 内存回收。
- 内核子系统的周期性或异步任务。

内核线程可以在合适的进程上下文中执行这些工作。

例如，工作队列（Workqueue）通常由内核工作线程执行，允许相关工作在可睡眠的上下文中完成。

这也是理解内核线程与中断下半部关系时需要掌握的背景。

# 九、进程终止（Process Termination）

进程终止是进程生命周期的最后一个阶段。

用户进程可以通过以下方式结束：

- 从 `main()` 返回。
- 调用 `exit()`。
- 调用 `_exit()` 或 `_Exit()`。
- 因信号而终止。
- 被其他进程或内核终止。

## 9.1 exit() 与 _exit()

需要区分 C 库中的 `exit()` 和系统调用层面的进程退出机制。

`exit()` 是 C 标准库函数，会执行用户态清理操作，例如：

- 调用通过 `atexit()` 注册的函数。
- 刷新并关闭标准 I/O 流。
- 最终请求内核终止进程。

`_exit()` 则直接请求内核终止进程，不执行 `exit()` 的用户态清理流程。

例如：

```c
#include <stdlib.h>
#include <unistd.h>

int main(void)
{
    exit(0);
}
```

在编写 `fork()` 后的子进程逻辑时，如果 `exec()` 失败，通常使用 `_exit()`，避免意外执行继承自父进程的用户态清理逻辑。

## 9.2 do_exit()

在书中所介绍的 Linux 内核实现中，进程退出的核心路径涉及 `do_exit()`。

其主要工作包括：

1. 释放进程占有的资源。
2. 处理内存管理相关资源。
3. 处理文件系统和文件描述符等资源。
4. 处理信号和退出通知。
5. 设置进程退出状态。
6. 通知父进程。
7. 将进程转入后续回收流程。

可以将其概括为：

```text
用户进程调用 exit()
        |
        v
    系统调用
        |
        v
     do_exit()
        |
        +---- 释放地址空间相关资源
        |
        +---- 释放文件等资源
        |
        +---- 处理退出通知
        |
        +---- 设置退出状态
        |
        v
   EXIT_ZOMBIE
        |
        | 父进程 wait()
        v
   最终释放进程描述符
```

这是概念上的简化流程，具体实现会涉及更多函数和状态转换。

## 9.3 wait() 与僵尸进程回收

父进程可以通过 `wait()` 或 `waitpid()` 获取子进程的退出状态。

例如：

```c
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <stdio.h>

int main(void)
{
    pid_t pid = fork();

    if (pid == 0) {
        _exit(42);
    }

    int status;
    waitpid(pid, &status, 0);

    if (WIFEXITED(status)) {
        printf("child exit code: %d\n", WEXITSTATUS(status));
    }

    return 0;
}
```

当子进程退出后，父进程通过等待系统调用获取退出状态，内核就可以完成最终的资源回收。

因此，**进程退出和进程彻底销毁并不是同一个时刻发生的事情。**

## 9.4 进程终止的资源释放

进程退出时，内核需要释放其持有的资源。

主要包括：

- 虚拟地址空间。
- 文件描述符。
- 文件系统相关资源。
- 信号处理相关资源。
- 其他内核对象。

不过，某些资源可能由多个进程或线程共享，因此不能简单地在一个任务退出时全部销毁。

例如：

如果多个线程共享同一个地址空间，那么一个线程退出时，不应直接释放整个进程的地址空间。

内核必须根据资源引用关系和线程组状态决定何时释放共享资源。

这也是 Linux 使用引用计数和共享资源管理机制的重要原因。

# 十、本章核心知识总结

## 10.1 核心数据结构

| 数据结构 | 作用 |
|---|---|
| `task_struct` | 描述和管理进程/线程 |
| `thread_info` | 保存与体系结构和线程执行相关的信息 |
| `mm_struct` | 描述进程的用户地址空间 |
| `files_struct` | 描述进程打开的文件描述符表 |
| `signal_struct` | 保存线程组共享的信号相关信息 |
| `sighand_struct` | 保存信号处理程序信息 |

这些结构之间存在复杂的关联关系。理解 `task_struct` 是阅读 Linux 进程管理源码的起点。

## 10.2 核心函数与接口

| 函数/接口 | 作用 |
|---|---|
| `current` | 获取当前任务 |
| `fork()` | 创建子进程 |
| `vfork()` | 创建子进程并暂时挂起父进程 |
| `clone()` | 按指定资源共享关系创建任务 |
| `exec()` | 用新程序映像替换当前进程 |
| `copy_process()` | 创建新任务时复制和初始化相关资源 |
| `do_fork()` | 书中历史内核实现中的进程创建路径 |
| `do_exit()` | 处理进程退出 |
| `wait()` | 等待并回收子进程退出状态 |

## 10.3 本章最重要的几个结论

1. **Linux 使用统一的 `task_struct` 描述进程和线程。** 进程和线程在内核中都是任务，区别主要在于资源共享关系。

2. **进程状态决定任务能否被调度。** `TASK_RUNNING` 同时包含正在运行和等待 CPU 的任务；睡眠状态则表示任务暂时不能运行。

3. **进程上下文和中断上下文必须区分。** 中断上下文通常不能睡眠，这是后续理解中断处理和内核同步的基础。

4. **`fork()` 通过写时复制降低进程创建开销。** 父子进程初始共享物理页面，只有发生写操作时才复制页面。

5. **`clone()` 是 Linux 线程实现的重要基础。** 不同资源共享标志决定了新任务与原任务之间的关系。

6. **进程退出与资源彻底释放是两个阶段。** 僵尸进程保留退出信息，等待父进程回收。

# 十一、建议进一步阅读的内核源码

本章最适合结合源码学习。建议先围绕任务描述符、进程创建和进程退出建立一条主线。

| 学习主题 | 建议关注的源码/符号 |
|---|---|
| 进程描述符 | `include/linux/sched.h` 中的 `task_struct` |
| 当前任务 | `current` 的体系结构相关定义 |
| 进程创建 | `fork`、`do_fork`、`copy_process`（书中对应版本） |
| 线程创建 | `clone` 及其资源共享标志 |
| 进程退出 | `do_exit` |
| 进程等待 | `wait`、`waitpid` 对应的内核实现 |
| 进程状态 | `TASK_RUNNING`、`TASK_INTERRUPTIBLE` 等定义 |

建议采用以下阅读顺序：

1. 先阅读 `task_struct`，明确内核如何描述一个任务。
2. 搜索 `current`，理解内核如何快速获取当前任务。
3. 从 `fork()` 入手，追踪进程创建过程。
4. 重点阅读 `copy_process()`，理解哪些资源被复制，哪些资源被共享。
5. 结合 COW 理解父子进程的地址空间关系。
6. 最后追踪 `do_exit()` 和 `wait()`，理解进程的退出与回收。

**版本说明：** 本章以《Linux Kernel Development》第三版所讨论的 Linux 内核机制为主。书中的部分函数名、数据结构布局和实现路径属于较早期内核版本。阅读 Linux 5.15 或 6.6 等现代内核时，应以对应版本的源码为准，不要将历史实现直接套用到现代内核。
