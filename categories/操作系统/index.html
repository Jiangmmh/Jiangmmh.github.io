再探xv6: 异常控制流篇

一、何为异常控制流 1. 从普通控制流到异常控制流 在学习操作系统之前，我们通常通过函数调用、条件分支、循环等机制理解程序的执行过程。 例如： int add(int a, int b) { return a + b; } int main(void) { int result = add(1, 2); return result; } 程序从 main() 开始执行，调用 add()，然后返回调用者。这种执行过程主要由程序自身的指令决定，我们可以称之为普通控制流。 然而，操作系统需要处理更多复杂的事件： 用户程序希望读取文件，需要请求内核提供服务。 网卡收到网络数据，需要通知 CPU 处理。 磁盘完成 I/O 操作，需要唤醒等待中的进程。 程序访问非法地址，需要由内核处理异常。 定时器触发，需要操作系统获得运行机会，进行调度。 这些事件可能发生在程序执行过程中的任意时刻，不能完全依赖当前程序主动调用函数来处理。 因此，计算机提供了一套特殊的控制流转移机制：当特定事件发生时，CPU 暂停当前执行路径，转而进入相应的处理程序。处理完成后，CPU 可以恢复原来的执行过程，也可能终止当前程序或切换到其他进程。 这种由异常、陷入和中断等事件引发的控制流转移，称为异常控制流（Exceptional Control Flow，ECF）。 理解异常控制流，需要回答三个问题： 什么事件触发了控制流转移？ CPU 如何找到处理程序，并切换到适当的执行环境？ 处理完成后，如何恢复原来的执行过程？ 在 xv6 中，系统调用和中断是理解这些机制的两个重要切入点。 2. 异常、陷入与中断 严格来说，异常控制流是一个广义概念。RISC-V 架构使用 trap 描述导致控制权转移到更高特权级处理程序的一类事件，主要包括同步异常和中断。 2.1 同步异常 同步异常由当前正在执行的指令直接引起，因此与程序执行位置存在明确的因果关系。 例如： 执行 ecall，主动请求操作系统服务。 执行非法指令。 访问未映射的虚拟地址。 违反内存访问权限。 同步异常的特点是：如果程序以相同状态重复执行到同一条指令，并且环境没有发生变化，那么通常会再次触发相同事件。 系统调用是其中一种特殊情况。用户程序执行 ecall 指令，主动请求从用户态进入内核态，因此也常被称为主动陷入。 2.2 中断 中断通常由当前指令执行之外的事件引起，例如外部设备发出的中断请求。 典型场景包括： UART 接收到新的输入数据。 磁盘控制器完成一次 I/O 操作。 网卡收到数据包。 定时器到期。 中断的特点是：它通常与 CPU 当前执行的指令没有直接因果关系。即使 CPU 正在执行完全无关的计算，外部设备仍然可能产生中断。 ...

一、简介 RISC-V的支持 RISC-V 指令（包括用户指令和内核指令）操作的是虚拟地址。而机器的RAM则需要使用物理地址来访问。RISC-V 页表硬件通过将每个虚拟地址映射到一个物理地址，将这两种地址连接起来。 xv6使用RISC-V的Sv39模式，其仅使用64位虚拟地址中低39位。在该设置下： 每个页面为4KB，使用低12位地址索引 采用三级页表，每级页表使用9位，共剩余27位进行索引 RISC-V 的设计为虚拟地址和物理地址的扩展都预留了空间。如果需要更多虚拟地址空间，RISC-V 支持 Sv48 模式，即 48 位虚拟地址。 下面是页表项的构成，包括了上述的39位物理地址和低10位的标志位。 PTE_V：指示了该PTE是否存在 PTE_R、PTE_W、PTE_X：指示可读、可写和可执行权限 PTE_U：控制该页面是否可以被用户程序访问 PTE_G、PTE_A：暂时未使用 RSW：还剩下两个保留位，可以根据需要来使用 每当执行RISC-V的访存指令时，就需要执行上述地址转换过程。在xv6的进程被调度上CPU时，会将进程根页目录表的地址存放到当前CPU的控制寄存器 satp 中。 多级页表虽然节省内存，但是访问某个页面中的数据需要多次访问内存，为了尽可能避免从虚拟地址到物理地址转换过程中的访存开销，RISC-V硬件提供了TLB（Translation Look-aside Buffer）来缓存部分虚拟地址到物理地址到映射，其思想和Cache类似，都是通过局部性原理构建。 内核地址空间 xv6 启动时会创建一个单页表，用于描述内核的地址空间，具体的布局定义见kernel/memlayout.h。 QEMU 模拟一台计算机，该计算机包含从物理地址0x80000000开始，直至0x88000000 。 其中大部分页面都采用对等映射（对等映射）实现（虚拟地址 == 物理地址），只有少数几个内核虚拟页面没有直接映射： 跳转页（Trampoline）。它被映射到虚拟地址空间的顶部；用户页表也具有相同的映射关系。一个物理页（包含跳转代码）在内核的虚拟地址空间中被映射了两次：一次在虚拟地址空间的顶部，另一次是直接映射。 内核栈保护页。每个进程都有自己的内核栈，它映射到较高的内核虚拟地址，这样 xv6 可以在其下方留下一个未映射的保护页。保护页的页表项 (PTE) 无效（即PTE_V未设置），因此如果内核栈溢出，很可能会导致缺页错误，内核崩溃。如果没有保护页，溢出的栈会覆盖其他内核内存，导致运行异常。崩溃崩溃是更可取的。 二、物理内存源码分析 物理内存的初始化 在main()函数中，调用了kinit()函数来初始化物理内存子模块： void kinit() { initlock(&kmem.lock, "kmem"); freerange(end, (void *)PHYSTOP); } 其中调用了freerange()函数，传入两个参数end和PHYSTOP，前者在链接脚本中被定义，位于 .text, .rodata, .data, .bss段之后的位置。后者的值为0x88000000，表示物理地址顶部。 void freerange(void *pa_start, void *pa_end) { char *p; p = (char *)PGROUNDUP((uint64)pa_start); for (; p + PGSIZE <= (char *)pa_end; p += PGSIZE) { kfree(p); } } 其中通过反复调用kfree()构造出一个存储4KB物理页帧的freelist。 struct run { struct run *next; }; struct { struct spinlock lock; struct run *freelist; } kmem; // Free the page of physical memory pointed at by pa, // which normally should have been returned by a // call to kalloc().
