Cow-Fork

MIT6.1810: Lab5 COW

一、fork 的实现原理 在用户态调用 fork() 后，程序通过系统调用进入内核，最终执行 sys_fork()，并在其中调用 kfork() 创建子进程。 kfork() 的主要工作包括： 调用 allocproc() 分配一个新的进程结构体，并完成必要的初始化。 调用 uvmcopy() 将父进程的用户地址空间复制到子进程。 将父进程的 Trapframe 拷贝到子进程，使子进程拥有与父进程相同的寄存器上下文。 遍历父进程打开的文件描述符，在子进程中通过 filedup() 增加对应文件对象的引用计数。 设置子进程的父进程信息，并将其状态设置为 RUNNABLE。 这里有一个比较巧妙的细节： // Cause fork to return 0 in the child. np->trapframe->a0 = 0; 为什么需要单独修改子进程 Trapframe 中的 a0？ 在 RISC-V 调用约定中，a0 用于传递函数参数和返回值。系统调用返回时，内核会将 Trapframe 中保存的 a0 恢复到用户态寄存器中。 因此： 父进程继续执行 fork() 后面的代码，系统调用返回值是子进程的 PID。 子进程第一次被调度时，从保存的上下文继续执行，系统调用返回值是 0。 这样，父子进程就能够通过 fork() 的返回值判断自己所处的执行分支。 下面是 kfork() 的核心实现（省略了部分与本实验无关的代码）： int kfork(void) { int i, pid; struct proc *np; struct proc *p = myproc(); // Allocate process. if ((np = allocproc()) == 0) return -1; // Copy user memory from parent to child. if (uvmcopy(p->pagetable, np->pagetable, p->sz) < 0) { freeproc(np); release(&np->lock); return -1; } np->sz = p->sz; // Copy saved user registers. *(np->trapframe) = *(p->trapframe); // Cause fork to return 0 in the child. np->trapframe->a0 = 0; // Duplicate open file descriptors. for (i = 0; i < NOFILE; i++) if (p->ofile[i]) np->ofile[i] = filedup(p->ofile[i]); np->cwd = idup(p->cwd); safestrcpy(np->name, p->name, sizeof(p->name)); pid = np->pid; release(&np->lock); acquire(&wait_lock); np->parent = p; release(&wait_lock); acquire(&np->lock); np->state = RUNNABLE; release(&np->lock); return pid; } 这里最值得关注的是 uvmcopy()。 ...
