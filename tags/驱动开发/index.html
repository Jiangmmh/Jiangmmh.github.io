一、内核模块简介 1.1 什么是内核模块？ Linux 内核采用模块化设计，允许开发者通过添加独立的软件组件来扩展内核功能，而不需要每次修改内核都重新编译整个内核。 内核模块（Kernel Module） 是一种能够在运行时动态加载到 Linux 内核中，并在不再需要时动态卸载的软件组件。 当内核模块用于控制和管理特定硬件设备时，它通常被称为设备驱动程序（Device Driver）。 例如： 网络设备驱动程序：负责管理网卡，处理网络数据包。 块设备驱动程序：负责管理磁盘、SSD 等存储设备。 字符设备驱动程序：负责管理串口、终端等字符设备。 文件系统模块：为内核提供额外的文件系统支持。 需要注意：并不是所有内核模块都是设备驱动程序。Linux 还使用模块实现文件系统、加密算法、网络协议以及其他可选内核功能。 1.2 静态模块与动态模块 Linux 内核功能可以通过两种方式集成到内核中。 1. 静态模块（Built-in Modules） 静态模块也称为内置模块。在构建内核时，通过配置文件 .config 选择需要启用的功能，并将对应源代码编译为目标文件，最终链接到内核映像文件中。 例如： CONFIG_EXT4_FS=y CONFIG_E1000=y 其中 y 表示将对应功能编译进内核。 优点： 不需要额外执行模块加载操作。 内核启动时即可使用相关功能。 不存在模块加载和卸载带来的额外管理开销。 缺点： 修改代码后通常需要重新构建内核。 无法在运行时独立卸载某个内置功能。 内置功能通常会一直占用内核映像及相应的运行时资源。 2. 动态模块（Loadable Kernel Modules，LKM） 动态模块与内核映像文件相互独立，通常以 .ko（Kernel Object）作为文件扩展名。 它们可以在系统运行期间动态加载和卸载。 例如： sudo insmod helloworld.ko sudo rmmod helloworld 优点： 不需要重新编译和启动整个内核即可扩展功能。 可以按需加载功能，减少不必要的内核常驻代码。 便于开发和调试驱动程序。 缺点： 模块必须与目标内核的版本、配置及符号接口兼容。 模块加载、卸载以及模块间依赖需要额外管理。 模块运行在内核态，错误可能导致整个系统崩溃。 补充： 动态模块虽然能够独立加载，但并不意味着它完全不依赖内核。模块仍然需要使用目标内核提供的头文件、配置、符号和构建环境。 1.3 内核模块相关配置 Linux 内核提供以下配置选项： ...
