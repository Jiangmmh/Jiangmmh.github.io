Linux 内核代码风格：官方规范与实践指南 原始文档：Linux kernel coding style 本文根据 Linux 内核官方文档整理，以中文概括核心规则并补充实践说明。具体开发时，应结合目标内核版本、所属子系统的现有代码和相关 API 文档。 代码风格并非单纯的排版问题。Linux 内核是一个由大量开发者长期协作维护的项目，统一的编码约定可以降低阅读成本，使代码审查更容易进行，也有助于发现资源管理、错误处理和并发访问中的问题。 本文按官方文档的主要主题梳理相关规范，并重点说明这些规则在 C 语言和 Linux 内核开发中的实际意义。 1. 缩进与代码布局 1.1 使用 8 字符宽度的制表符缩进 Linux 内核传统代码风格使用 Tab 进行缩进，Tab 宽度为 8 个字符。不要将普通空格当作代码块的缩进字符。 static int process_item(int value) { if (value < 0) return -EINVAL; return handle_item(value); } 较宽的缩进能够突出代码层级。当函数需要过多缩进时，也是在提醒开发者：控制流可能过于复杂，需要重新审视函数结构。 1.2 避免一行写多个语句 不要为了节省行数而将多个语句挤在一行，也不要通过逗号运算符绕过大括号约定。 不推荐： if (condition) do_this(); do_that(); 更清晰的写法： if (condition) { do_this(); do_that(); } 对于包含多个操作的分支，应使用大括号明确划分代码块。 1.3 避免过深的嵌套 过多的条件分支和循环会增加理解成本。与其不断增加缩进，不如考虑： 提前处理错误条件并返回。 将独立职责拆分为辅助函数。 简化条件表达式。 减少不必要的控制流层级。 1.4 控制行长度 官方文档建议通常将单行长度控制在 80 列左右。超长语句应根据逻辑结构合理换行，但不要为了机械满足列数而牺牲可读性。 函数参数较多时，可以按参数列表的结构进行对齐。 另外，不要随意拆分用户可见的日志字符串，否则会增加通过日志文本检索代码的难度。 2. 大括号、空格与运算符 2.1 大括号的位置 对于 if、switch、for、while 等非函数代码块，通常将左大括号放在控制语句行末尾： ...
