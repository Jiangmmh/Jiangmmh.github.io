内存管理

关于C++智能指针

1. 简介 1.1 动态内存管理 在 C++ 中，内存管理一直是一个重要而又容易出错的问题。理解智能指针之前，我们需要先回答一个问题：为什么程序需要动态内存？ 为什么需要动态内存？ 在程序中，我们经常需要创建对象。对于生命周期和数量都能够提前确定的对象，可以直接使用局部变量、全局变量或其他具有适当存储期的对象。然而，在很多实际场景中，程序无法在编译时确定所需对象的数量、具体类型，甚至无法确定对象应该在什么时候销毁。 动态内存管理正是为了解决这些问题而存在的。 1. 程序不知道自己需要多少对象 考虑一个读取用户输入并处理数据的程序： #include <iostream> #include <vector> int main() { int n; std::cin >> n; std::vector<int> data(n); for (int i = 0; i < n; ++i) { std::cin >> data[i]; } // 处理数据 } 程序在运行之前并不知道用户会输入多少个整数。数据量取决于运行时的输入，因此程序需要在运行时管理相应的存储空间。 这里使用 std::vector，它能够根据需要管理动态分配的内存。我们不必手动申请和释放底层存储空间。 需要注意的是，动态内存并不意味着必须显式调用 new。标准容器、字符串以及其他资源管理类型已经封装了大量动态内存管理工作。 2. 程序不知道所需对象的准确类型 在面向对象程序中，我们可能需要根据运行时的信息创建不同类型的对象。 例如，一个图形程序需要处理圆形和矩形： #include <memory> struct Shape { virtual ~Shape() = default; virtual void draw() = 0; }; struct Circle : Shape { void draw() override { // 绘制圆形 } }; struct Rectangle : Shape { void draw() override { // 绘制矩形 } }; std::unique_ptr<Shape> createShape(bool isCircle) { if (isCircle) { return std::make_unique<Circle>(); } return std::make_unique<Rectangle>(); } 调用者只需要知道自己获得了一个 Shape 对象，而不必提前确定其具体类型。 这类设计广泛存在于插件系统、图形界面、游戏引擎和各种基于多态的程序中。 ...
