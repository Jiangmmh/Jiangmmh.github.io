Linux是一种开源的操作系统，你有任何疑问都可以从源代码和文档中找到答案，即使你看不懂源代码，也找不到文档，也很容易找个高手教你，各种邮件列表、新闻组和论坛上从来都不缺乐于助人的高手；而Windows是一种封闭的操作系统，除了微软的员工别人都看不到它的源代码，只能通过文档去猜测它的工作原理，更糟糕的是，微软向来喜欢藏着揶着，好用的功能留着自己用，而不会写到文档里公开。 1. 程序和编程语言 程序 = 一组指令序列指令，指令无外乎以下几类： 输入指令，从外部设备读入数据 输出指令，向外部设备输出数据 基本运算，执行算数逻辑运算和访问 测试和分支指令，根据当前状态选择不同的指令执行路径 循环指令，重复执行一组操作 无论程序如何复杂，最终都会落到这些些指令上。 编写程序可以说就是这样一个过程：把复杂的任务分解成子任务，把子任务再分解成更简单的任务，层层分解，直到最后简单得可以用以上指令来完成。 平台 = 体系结构 + 操作系统 + 开发库（编译器和链接器） 高级语言是平台无关的，所以绝大部分程序是用高级语言编写的，只有和硬件关系密切的少数程序（例如驱动程序）才会用到低级语言。 注意：即使在相同的体系结构和操作系统下，用不同的C编译器（或者同一个C编译器的不同版本）编译同一个程序得到的结果也有可能不同，C语言有些语法特性在C标准中并没有明确规定，各编译器有不同的实现，编译出来的指令的行为特性也会不同，应该尽量避免使用不可移植的语法特性。 总结：程序由语句或指令组成，计算机只能执行低级语言中的指令（汇编语言的指令要先转成机器码才能执行），高级语言要执行就必须先翻译成低级语言，翻译的方法有两种－－编译和解释，虽然有这样的不便，但高级语言有一个好处是平台无关性。 习题：解释执行的语言相比编译执行的语言有什么优缺点？ 背景知识：高级语言提供了较高的抽象，大大提高了程序员开发软件的效率，但是机器只能执行一组简单的指令，所以必须先将高级语言程序翻译为机器代码。 在讨论编译和解释的优缺点之前，先认识一下两者的基本概念： 解释：每读取一条命令，就立即将其翻译为机器代码进行执行，直至执行完毕或出现错误 编译：先从头到尾读取源文件，将其翻译为机器代码，然后再执行 解释相比编译执行的优缺点： 优点：非常灵活，在源文件被修改之后无需重新编译 缺点：在运行时进行翻译，性能不如编译执行，并且无法在程序运行前检查出程序中的错误 形式语言（Formal Language）是为了特定应用而人为设计的语言，它必须按照特定的格式进行表达。例如数学家用的数字和运算符号、化学家用的分子式等。编程语言也是一种形式语言，是专门设计用来表达计算过程的形式语言。 语法规则 = 由符号（Token，词法）+ CS161 Computer Security Lec1

我的学习结合了26sping和26fall的材料，即slides看26sp，课程视频看26fa。 教材阅读笔记 这是教材第一章内容的笔记，主要介绍了13个安全原则。 1. 了解你的威胁模型 威胁模型（threat model） 是对攻击者身份及其所拥有资源的描述。 攻击者攻击系统的原因多种多样，可能是金钱、政治、娱乐等等。有些攻击者毫无逻辑可言——他们只是想看世界毁灭。以你自身的人身安全为例。了解你的威胁模型，就意味着了解谁会以及为什么会攻击你 我们通常会对攻击者给出如下常见的假设： 攻击者可以在无人察觉的情况下与您的系统进行交互，这意味着您可能无法总能在攻击者发动攻击之前检测到他们篡改您的系统。 攻击者掌握了一些关于您系统的基本信息，例如操作系统、任何潜在的软件漏洞等等。 攻击者坚持不懈，而且运气不错（不要有侥幸心理）；例如，如果一次攻击成功的概率是百万分之一，那么攻击者就会尝试一百万次。 攻击者愿意投入时间和资源进行攻击。 攻击者可以协调跨多个系统的复杂攻击。攻击者不仅限于攻击单个设备，还可以同时攻击整个网络，或将多个攻击串联起来。 任何系统都可能成为攻击目标。例如，一家赌场曾遭到黑客攻击，原因是其网络中的一个鱼缸温度计被入侵。 2. 考虑人为因素 安全系统必须方便普通用户使用，因此在设计时必须考虑到人为因素。 如果一个安全系统不好用、不人性化，无论它多么安全，最终都会无人问津。 如果某种方法能让用户的更方便使用，那他们总会找到办法来规避安全系统。 3. 安全即经济学 经济学是一门研究人们如何在资源有限的情况下做出选择的社会科学。 安全其实与经济学类似。没有任何系统能够完全抵御所有攻击，更高级别的安全通常需要投入更多资金，因此防御措施的预期收益应该与攻击的预期成本成正比。 这条原则的推论是：你应该集中精力加固最薄弱的环节。安全就像一条链条：一个系统的安全性取决于它最薄弱的环节。攻击者会选择阻力最小的路径，他们会攻击系统最薄弱的地方。在纱门上安装昂贵的高档防盗锁毫无意义；攻击者不会费力去撬锁，他们可以直接拆掉纱门走进去。 4. 如果无法预防，请进行检测 预防是指阻止攻击发生，检测是指获悉攻击已经发生，而响应是指对攻击采取应对措施。 如果无法阻止攻击发生，至少应该能够知道攻击已经发生。一旦知道攻击已经发生，就应该找到应对方法，因为没有响应的检测毫无意义。 5. 纵深防御 纵深防御的关键思想是将多种类型的防御措施分层叠加，这样攻击者就必须突破所有防御才能成功攻击系统。 纵深防御的一个例子是通过探测器的组合。假设你有两个探测器，D1和D2这两个探测器都有一定的误报率（并非实际安全漏洞的警报）和漏报率（未触发任何警报的安全漏洞）。一种使用方法是将这两个探测器并联，即任何一个探测器发出警报都会触发响应。这样可以提高误报率，降低漏报率。另一种方法是将探测器串联，即两个探测器都必须发出警报才能触发响应。在这种情况下，误报率会降低，而漏报率会升高。 6. 最小权限原则 为了确保最佳安全，任何一方都应仅拥有履行其职责所需的最小权限。 程序拥有的权限越少，即使将来遭受缓冲区溢出攻击，造成的损害也越小。 Unix 在最小权限原则方面做得如何？答案是：非常糟糕。每个程序都会获得调用它的用户的所有权限。 Windows表现如何？答案：同样糟糕。 移动设备在这方面做得更好。每个应用程序都运行在沙盒环境中，通常无法访问其他应用程序的数据。 7. 责任分离 分散权限，避免任何个人或程序拥有绝对权力。要求在授予访问权限前必须获得多方批准。 如果你需要保护一项高度敏感的行动，就应该要求多方合作来执行该行动，因为单方恶意行事的可能性比所有参与方都恶意行事并相互勾结的可能性要大得多。 8. 确保完全中介（Ensure Complete Mediation） 每一次对受保护资源的访问，都必须经过权限检查。 执行访问控制策略时，必须检查对每一个对象的每一次访问。 这里有两个关键词： Every access（每一次访问）：不能只在登录时检查，也不能只检查第一次访问。读取、修改、删除等操作，都必须受到适当的访问控制。 Every object（每一个对象）：不能只保护部分资源。文件、数据库记录、账户、API 资源等，都要纳入相应的权限控制范围。 9. 香农定律 香农格言指出，攻击者了解他们正在攻击的系统。 “隐蔽式安全”指的是依靠系统设计、算法或源代码的保密性来保障安全的系统。 ...

一生一芯-F3阶段笔记

处理器芯片本质上是数字电路。数字电路是用来处理数字信号的电路, 而数字信号简单来说是指0和1这两种离散的信号. 这里的0和1并不是数学意义上的自然数, 它是指信号的两种不同状态, 为了简单叙述, 就分别称它们为0和1. 为了和数学上的0和1区分开来, 有时候也将上面两种状态称为逻辑0和逻辑1。 因此, 处理器芯片本质上也是处理0和1这两种信号的芯片. 要学习处理器芯片设计, 数字电路的知识是基础. 而要学习数字电路, 就是需要学习信息在数字电路中是如何表示, 处理和存储的。具体地, 你将会了解: 如何表示 - 数字信号0和1在数字电路中的物理含义 如何处理 - 门电路和组合逻辑电路的工作原理 如何存储 - 时序逻辑电路的工作原理 课程笔记 1. 如何表示0和1？ 关键问题：数字电路如何表示0和1（物理含义），以及如何处理它们？ 数字电路用物理量的两个离散区间表示 0 和 1：最常见的是低电平=0、高电平=1，并用阈值区间和噪声容限保证在真实电路中可靠区分，而不是依赖精确的单一电压值。 使用晶体管处理数字信号：一个晶体管包含三个极（Source、Drain和Gate），其作用类似于一个开关，通过在Gate端加入不同电压可以控制Source和Drain的导通与断开。 2. CMOS 在实际的硬件设计中，通常使用一个nMOS和一个pMOS构造CMOS来实现0和1。 下面这个CMOS本身其实是一个反相器，即输入A为0，输出Y为1；输入A为1，输出Y为0。 关键问题：一个晶体管就能作为开关，为什么要用两个晶体管构成CMOS？ 单看逻辑功能，一个 nMOS 确实就能当开关用——栅极给高电平导通、给低电平截止。那为什么几乎所有的现代数字电路都用 CMOS（互补金属氧化物半导体，即 nMOS + pMOS 配对）而不是单管方案？ nMOS擅长传递低电平，pMOS擅长传递高电平，反过来会导致信号衰减。 CMOS的静态功耗低。 CMOS的互补结构使高低电平的噪声容限对称、较大。 CMOS 工艺中 NMOS 和 PMOS 可以成对制造，版图规整、易于自动布局布线，也便于用标准单元库大规模综合。单管方案往往需要电阻、特殊器件，难以标准化和缩放。 虽然一个晶体管也能"通断"，但只有 nMOS + pMOS 互补配对，才能同时做到：完整传递 0 和 1、主动驱动、静态几乎不耗电、电平可恢复、易于大规模集成。 CMOS 不是"两个管子干一个管子的活"的浪费，而是用互补换来了功耗、电平、可靠性、可扩展性的全面胜利。 ...
